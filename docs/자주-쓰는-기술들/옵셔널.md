# 옵셔널 다루기 (Optionals)

> Swift 에서 "값이 있을 수도, 없을 수도 있다" 를 타입으로 표현하는 장치. Java 의 `Optional<T>` 와 가장 가깝다.

---

## 1. 옵셔널이란

Swift 의 `String?` 은 사실 **`Optional<String>` 이라는 enum 의 축약 표기**다.

```swift
// 이 둘은 정확히 같다
var a: String? = "hi"
var b: Optional<String> = .some("hi")

var c: String? = nil
var d: Optional<String> = .none
```

즉 `T?` 는

```swift
enum Optional<Wrapped> {
    case some(Wrapped)
    case none
}
```

의 sugar. 그래서 **값을 쓰려면 enum 을 풀어야** 한다.

### Java / JS 와 비교

| 언어 | "값이 없을 수도 있다" 표현 | 강제로 풀어야 하나? |
|---|---|---|
| Java | `Optional<T>` | 예 (`.get()` / `.orElse(...)`) |
| Swift | `T?` (= `Optional<T>`) | 예 (`if let` / `!` / `??` 등) |
| JS / TS | `T \| null \| undefined` | 아니오 — 그냥 쓰면 런타임 오류 |

→ Swift 의 옵셔널은 **JS 의 nullable 가 아니다**. 컴파일러가 강제로 풀어쓰게 만든다.

---

## 2. 옵셔널 만들기

```swift
var name: String? = "Jeon"     // .some("Jeon")
var nick: String? = nil        // .none
var age: Int?                  // 기본값 nil

func find(id: Int) -> User? {  // 못 찾으면 nil 리턴
    // ...
}
```

함수 반환 타입에 `?` 가 붙어 있으면 "못 찾을 수도 있다" 라는 시그널.

---

## 3. 옵셔널 푸는 6가지 방법

### 3-1. `if let` — 가장 기본

```swift
if let window = NSApplication.shared.windows.first {
    // 블록 안에서 window 는 NSWindow (옵셔널이 풀린 상태)
    window.title = "Hi"
}
// 블록 밖에선 window 변수 못 씀
```

Swift 5.7+ 에서는 **같은 이름이면 우변 생략 가능** (shadowing):

```swift
let folder: Folder? = ...
if let folder {            // = if let folder = folder
    print(folder.name)
}
```

> Java 비유:
> ```java
> Optional<Window> w = ...;
> if (w.isPresent()) {
>     Window window = w.get();
>     // ...
> }
> ```
> Swift 의 `if let` 은 위 두 줄을 한 줄로 합친 것.

### 3-2. `guard let` — 조기 탈출

이 함수의 나머지 로직을 돌리기 전에 **nil 이면 그냥 빠져나가고 싶을 때**.

```swift
func save(folder: Folder?) {
    guard let folder else { return }   // nil 이면 여기서 끝
    // 이 줄 이후로 folder 는 풀린 Folder (강제 언래핑 아님)
    context.insert(folder)
}
```

- `else { ... }` 블록에선 **반드시 함수를 빠져나가야** 한다 (`return` / `throw` / `fatalError` 등).
- 빠져나간 이후로는 `folder` 가 **함수 끝까지** 풀린 상태로 살아 있다. → `if let` 처럼 블록에 갇히지 않음.

**언제 `if let` vs `guard let`?**

- "값이 있을 때만 뭔가 하고 싶다" → `if let`
- "값이 없으면 더 진행 못 한다" → `guard let`

이 프로젝트 코드에서 자주 보이는 패턴 (`docs/09-.../04-...`):

```swift
guard !trimmed.isEmpty else { return }
guard let folder = selectedFolder, !trimmed.isEmpty else { return }
```

→ guard 는 **여러 조건을 콤마로 묶을 수 있다.**

### 3-3. `??` — 기본값 제공 (nil-coalescing)

값이 있으면 그걸, 없으면 우변 값을 쓴다.

```swift
let name: String? = nil
let display = name ?? "익명"      // "익명"

let count = items.first?.count ?? 0
```

> Java 비유: `Optional.orElse("익명")`
> JS 비유: `name ?? "익명"` (Swift 와 거의 동일)

### 3-4. `?.` — 옵셔널 체이닝

옵셔널인 값에 `.` 으로 메서드/프로퍼티 접근할 때 nil 이면 **그냥 nil 로 끝**.

```swift
window?.standardWindowButton(.closeButton)?.alphaValue = 0
//    ^ window 가 nil 이면 여기서 nil 반환하고 끝
//                                         ^ 이 버튼이 nil 이어도 nil 반환하고 끝
```

체이닝 결과 전체가 옵셔널이 된다:

```swift
let title: String? = window?.title          // window nil 이면 title 도 nil
let len:   Int?    = window?.title?.count   // 어느 단계든 nil 이면 결과 nil
```

> JS 의 `?.` 와 의미가 거의 같다.
> Java 로 치면 `Optional.map(w -> w.getTitle()).map(t -> t.length())` 패턴.

### 3-5. `try?` — 에러 → 옵셔널

`throws` 함수 호출 시, 에러가 나면 nil 로 변환.

```swift
let data = try? Data(contentsOf: url)   // 실패하면 nil
// 비교: try → 에러 발생 시 함수 밖으로 throw
//      try! → 실패 시 크래시
```

SwiftData 에서도 종종 마주친다:

```swift
try? context.save()
```

→ "save 실패해도 그냥 넘어가" 의미. 학습 단계에선 OK 지만 **프로덕션 코드에선 do/catch 로 로깅** 하는 게 정석.

### 3-6. `!` — 강제 언래핑 (지양)

```swift
let url = URL(string: "https://...")!   // nil 이면 즉시 크래시
```

- **확실히 nil 이 아닐 때만** 쓴다.
- 상수 리터럴 URL / 번들 리소스 / 테스트 코드 정도가 정당화 가능한 범위.
- 일반 코드에서 `!` 가 자주 보이면 코드 리뷰에서 반려된다.

## 4. 자주 만나는 패턴

### 4-1. 옵셔널 비교

옵셔널은 `==` / `!=` 로 nil 과 직접 비교 가능. 값끼리 비교도 됨.

```swift
if name == nil { ... }
if name != nil { ... }
if name == "Jeon" { ... }   // name 이 nil 이면 false
```

### 4-2. 옵셔널 배열 vs 배열 옵셔널 — 헷갈리지 말기

```swift
var a: [String]?    // 배열 자체가 nil 일 수도 있음
var b: [String?]    // 배열은 있지만 원소가 nil 일 수도 있음
var c: [String?]?   // 둘 다
```

### 4-3. `compactMap` — nil 걸러내며 풀기

```swift
let names: [String?] = ["a", nil, "b"]
let filtered: [String] = names.compactMap { $0 }   // ["a", "b"]
```

> Java 의 `stream().filter(Objects::nonNull)` + `.map(Optional::get)` 와 동일한 결.

### 4-4. SwiftUI `@State` 옵셔널 + sheet / alert 표시

```swift
@State private var editing: Folder? = nil

// editing 이 nil 이 아닐 때만 sheet 표시
.sheet(item: $editing) { folder in
    EditFolderView(folder: folder)
}
```

→ `sheet(item:)` 은 옵셔널이 `.some` 이면 표시, `nil` 이면 닫는다. 옵셔널을 **존재 토글** 로 활용하는 SwiftUI 관용구.

### 4-5. 옵셔널 함수 매개변수

```swift
func greet(_ name: String? = nil) {
    print("Hi, \(name ?? "stranger")")
}

greet()              // "Hi, stranger"
greet("Jeon")        // "Hi, Jeon"
greet(nil)           // "Hi, stranger"
```

## 5. 잘 안 쓰지만 만나면 당황하는 것

### Implicitly Unwrapped Optional `T!`

```swift
var label: UILabel!
```

선언상 옵셔널이지만 **접근 시 자동으로 강제 언래핑** 되는 타입. nil 이면 즉시 크래시.

- 주로 **AppKit / UIKit IBOutlet** 등 "초기화 직후 즉시 채워짐이 보장된" 자리에 쓴다.
- SwiftUI 만 쓸 거면 거의 만날 일 없다.

### `switch` 로 풀기

```swift
switch name {
case .some(let value):
    print(value)
case .none:
    print("없음")
}
```

→ 가독성 떨어져서 잘 안 씀. `if let` / `guard let` 이 표준.

---

## 6. 의사결정 치트시트

| 상황 | 추천 |
|---|---|
| 값 있으면 처리, 없으면 무시 | `if let` |
| 값 없으면 함수 중단 | `guard let ... else { return }` |
| 값 없을 때 기본값으로 대체 | `??` |
| 옵셔널 객체의 메서드/프로퍼티만 잠깐 건드림 | `?.` |
| 에러 함수를 옵셔널로 받기 | `try?` |
| nil 이 절대 아님이 확실 (그래도 신중) | `!` |
| 옵셔널 배열에서 nil 제거 | `.compactMap { $0 }` |

---

## 7. 이 프로젝트에서 자주 쓰는 곳

- **AppKit 접근**: `NSApplication.shared.windows.first` 가 옵셔널 → `if let` (`docs/01-...`)
- **SwiftData 쿼리 결과 first 접근**: `folders.first` → 옵셔널
- **선택 상태**: `@State var selectedFolder: Folder? = nil` → sheet/alert 표시 토글
- **저장 가드**: `guard let folder = selectedFolder, !name.isEmpty else { return }` 형태 (`docs/09-.../05-...`, `07-...`)

---

## 조금 더 (선택)

- **Optional 도 `map` / `flatMap` 이 있다** — Java Optional 과 거의 동일. `let upper = name.map { $0.uppercased() }` 는 name 이 nil 이면 nil, 아니면 대문자 String?.
- **`as?` 다운캐스팅** — `let folder = sender as? Folder` 처럼 캐스팅도 결과가 옵셔널이다.
- **`Result<Success, Failure>`** — "성공/실패" 를 표현하는 별도 타입. 옵셔널과 자주 비교되지만, 실패 이유까지 담을 수 있다는 점이 다르다.
