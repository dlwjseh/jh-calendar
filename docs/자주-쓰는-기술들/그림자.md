# 그림자 (Shadow)

> SwiftUI 의 `.shadow(...)` 모디파이어로 뷰 뒤에 그림자를 깐다. CSS `box-shadow` 와 거의 같은 모델 (offset + blur + color).

---

## 1. 기본 시그니처

```swift
.shadow(color: Color, radius: CGFloat, x: CGFloat = 0, y: CGFloat = 0)
```

- **color**: 그림자 색. 보통 `.black.opacity(...)` 로 톤 조절.
- **radius**: 흐림 정도(blur). 크면 부드럽고 멀리 퍼지는 느낌. 0 이면 또렷한 복사본.
- **x / y**: 그림자가 떨어지는 방향. **양수 y = 아래쪽**. 빛이 위에서 내려온다고 보면 됨.

```swift
RoundedRectangle(cornerRadius: 12)
    .fill(.background)
    .shadow(color: .black.opacity(0.3), radius: 20, y: 8)
```

> CSS 비유: `box-shadow: 0 8px 20px rgba(0,0,0,0.3);`
> 단 SwiftUI 는 **spread** 파라미터가 없다 (블러로만 표현).

---

## 2. 이 프로젝트의 두 가지 프리셋

이 코드베이스에서 실제로 쓰는 값은 두 종류뿐.

### 2-1. 가벼운 그림자 — 플로팅 위젯

[`FloatingToolbar.swift`](../../JHCalendar/Features/FloatingToolbar/FloatingToolbar.swift):

```swift
.shadow(color: .black.opacity(0.1), radius: 7, x: 0, y: 2)
```

→ "본문 위에 살짝 떠 있는" 느낌. 캡슐 토글바처럼 **항상 보여 있는 작은 위젯** 용.

### 2-2. 강한 그림자 — 모달/팝업

[`AddFolderDialog.swift`](../../JHCalendar/Features/Sidebar/AddFolderDialog.swift), [`AddCategoryDialog.swift`](../../JHCalendar/Features/Sidebar/AddCategoryDialog.swift), [`AddEventDialog.swift`](../../JHCalendar/Features/Event/AddEventDialog.swift), [`DayPopupDialog.swift`](../../JHCalendar/Features/Event/DayPopupDialog.swift):

```swift
.shadow(color: .black.opacity(0.3), radius: 20, y: 8)
```

→ "본문에서 멀찍이 떠 있다, 모달이다" 느낌. **사용자 주의를 끌어야 하는 카드**용.

새 다이얼로그/팝업을 만든다면 두 번째 값을 그대로 복붙해서 톤 통일하는 게 좋다.

---

## 3. 모디파이어 순서 = 결과가 달라진다

SwiftUI 모디파이어는 **체인 순서대로 위에서 아래로 감싼다**. 그림자도 "그 시점의 뷰 외곽" 에 그려져서 순서가 중요.

### 3-1. `clipShape` 와의 관계

```swift
// ❌ 잘못된 순서 — clip 전에 shadow → 사각형 그림자가 카드 모서리 밖에 새어 나옴
.shadow(...)
.clipShape(.rect(cornerRadius: 12))

// ✅ 옳은 순서 — clip 후 shadow → 둥근 모서리 따라 그림자
.clipShape(.rect(cornerRadius: 12))
.shadow(...)
```

이 프로젝트 다이얼로그들이 전부 `background → clipShape → shadow` 순서인 이유.

### 3-2. `background` 와의 관계

`.shadow` 는 **현재 뷰** 의 외곽에 그림자를 그린다. background 가 없으면(예: 투명한 텍스트) 글자 모양대로 그림자가 깔린다.

```swift
Text("Hello")
    .shadow(radius: 3)   // 글자에 그림자 (텍스트 효과)

Text("Hello")
    .padding()
    .background(.white, in: .rect(cornerRadius: 6))
    .shadow(radius: 3)   // 카드에 그림자
```

→ "카드 그림자" 를 원하면 반드시 `background` 가 먼저 와야 한다.

### 3-3. 자식까지 전파

`.shadow` 는 부모에 걸어도 **컨테이너의 외곽** 에만 그림자가 생긴다 (CSS 와 동일). 자식 각각에 그림자 주려면 자식마다 `.shadow` 를 건다.

---

## 4. 그림자 여러 개 쌓기

여러 번 호출하면 누적된다. 진짜 같은 깊이감을 내는 흔한 기법.

```swift
.shadow(color: .black.opacity(0.15), radius: 1, y: 1)   // 또렷한 가까운 그림자
.shadow(color: .black.opacity(0.10), radius: 20, y: 10) // 멀고 부드러운 그림자
```

> Material Design / Apple 디자인 가이드의 elevation 도 보통 **두 겹** (key shadow + ambient shadow) 이다.

이 프로젝트는 한 겹으로 끝내지만, 더 사실적인 그림자가 필요해지면 이렇게 두 줄로.

---

## 5. Material 배경과의 궁합

```swift
.background(.ultraThinMaterial)
.clipShape(.capsule)
.shadow(color: .black.opacity(0.1), radius: 7, y: 2)
```

`FloatingToolbar` 패턴. Material 은 반투명 블러라 그 자체로 "떠 있는" 느낌이 있어서 **그림자는 약하게** 가는 게 자연스럽다. `.opacity(0.3)` 같은 강한 그림자 + Material 은 어색해진다.

---

## 6. 컬러 / 다크모드

```swift
.shadow(color: .black.opacity(0.3), ...)   // 라이트/다크 모두 검정 그림자
```

- 다크모드에선 검정 그림자가 잘 안 보일 수 있다. 그래도 미세한 입체감은 남으니 대개 이대로 OK.
- 정말 다크모드 대응이 필요하면 `@Environment(\.colorScheme)` 으로 분기하거나, 아예 톤 차이 있는 `.primary.opacity(...)` 같이 시멘틱 컬러를 시도해볼 수 있음. (이 프로젝트는 아직 그렇게까지 안 함.)

---

## 7. 성능 — 신경 써야 할 때

`.shadow` 는 GPU 에서 합성되지만, **블러 반경이 큰 그림자 + 자주 리렌더되는 큰 뷰** 조합은 비싸질 수 있다.

| 상황 | 비용 |
|---|---|
| 작은 카드/툴바에 정적 그림자 | 무시 가능 |
| 다이얼로그 등장 시 한 번 그림 | 무시 가능 |
| 스크롤 리스트의 매 셀에 큰 블러 그림자 | 60fps 떨어질 수 있음 |
| 애니메이션 중인 큰 뷰에 `radius: 30` 짜리 그림자 | 조심 |

**증상 보이면 시도해볼 것**
- `radius` 줄이기 (블러가 가장 비싸다)
- `drawingGroup()` 으로 Metal 합성 강제 — 정적인 화면엔 효과적, 자주 갱신되면 오히려 손해
- 진짜 무거우면 그림자를 이미지(미리 렌더된 비트맵)로 대체

> 이번 프로젝트 규모에선 다 무시 가능. 측정도 안 하고 미리 최적화하지 말 것.

---

## 8. 흔한 함정

1. **`y` 음수 = 위쪽 그림자.** 보통은 양수 (`+y` 아래로 떨어짐) 가 자연스럽다.
2. **`clipShape` 후에 `shadow` 안 걸면 모서리 안 따라간다.** §3-1 참고.
3. **글자에 강한 그림자는 가독성을 망친다.** UI 카드 그림자와 텍스트 그림자는 다른 용도. 텍스트엔 `radius: 1~2` 정도.
4. **`color: .black` 자체가 진하다.** opacity 안 주면 너무 강해 보임. 항상 `.opacity(0.05~0.3)` 범위로.
5. **`.shadow(radius: 0)` 은 그림자 없음이 아니라 "또렷한 복사본".** 그림자를 끄려면 모디파이어 자체를 빼거나 `color: .clear`.

---

## 9. 의사결정 치트시트

| 원하는 느낌 | 값 |
|---|---|
| 살짝 떠 있는 위젯 (툴바, 버튼바) | `color: .black.opacity(0.1), radius: 7, y: 2` |
| 모달/팝업/대화상자 | `color: .black.opacity(0.3), radius: 20, y: 8` |
| 글자 강조 (드물게) | `radius: 1~2, y: 1` |
| 사실적 깊이감 (두 겹) | 가까운 한 줄 + 멀고 부드러운 한 줄 |
| 그림자 끄기 | 모디파이어 제거 (또는 `color: .clear`) |

## 조금 더 (선택)

- **`ShadowStyle` (iOS 16+/macOS 13+)** — `.shadow(.drop(color:radius:x:y:))` / `.shadow(.inner(...))` 형태로 `ShapeStyle` 에 직접 그림자 부여. `Shape` 에 쓸 때 더 표현력 있음.
- **Inner shadow (안쪽 그림자)** — SwiftUI 기본 `.shadow` 는 outer 만. 안쪽 그림자는 위 `ShadowStyle.inner` 또는 `Shape` 의 `.fill` 에 `.shadow(.inner(...))` 로 가능.
- **`compositingGroup()`** — 모디파이어 순서로 안 풀리는 합성 이슈가 나면 그룹 경계를 명시. 그림자가 자식들에 따로 그려지는 걸 막을 때.
- **`drawingGroup()`** — 정적인 복잡한 뷰를 Metal 한 장으로 렌더. 그림자 많은 정적 화면 최적화용.
