# 단계 5: 셀에서 멀티데이 그리기 끄기 (분기)

> 새 개념 없음. 03 의 `isMultiday(_:)` 한 줄을 셀에 적용해서 **셀은 단일 일만** 그리도록 분기.

## 작업 목표
04 단계까지는 셀 안 토막 바와 행 overlay 바가 **겹쳐서** 보인다. 이번 단계에서 **셀이 멀티데이 이벤트를 그리지 않게** 분기해 토막 바를 제거한다.

## 사전 산출물
- `isMultiday(_:)` — 03 에서 `EventIndex.swift` 에 추가됨.

## 작업 가이드

선택지가 두 군데에 있다.

**A. 셀(`DayCellView`) 안에서 분기**

`ForEach(events.prefix(maxVisible))` 의 본문 첫 줄에 `if isMultiday(e) { EmptyView } else { ... 기존 ... }`. 단점: `prefix(maxVisible)` 가 먼저 적용되니, 단일 일이 가려질 수 있음.

**B. 부모(`MonthlyCalendarView` 또는 `WeekRowView`) 에서 미리 단일 일만 잘라 넘김** ← 권장

셀로 넘기는 events 자체를 단일 일만 거른 사전으로 교체.

```swift
// EventIndex.swift 또는 MonthlyCalendarView 안
private var singleDayEventsByDayIndex: [Date: [Event]] {
    eventsByDay(events.filter { !isMultiday($0) }, calendar: calendar)
}
```

또는 더 통합적으로 `eventsByDay` 호출 시 `filter` 한 입력을 넘기는 방식. 핵심은 **셀이 받는 사전엔 멀티데이가 없다** 는 것.

호출부:

```swift
WeekRowView(row: row,
            eventsByDayIndex: singleDayEventsByDayIndex,   // ← 변경
            weekMultidays: multidaysByWeek[...] ?? [],
            onSelectDay: { ... })
```

> 이렇게 하면 **셀은 여전히 자기가 받는 것만 그린다** ([11-03 의 "멍청한 셀" 원칙](../11-달력-이벤트-표시/03-날짜별-인덱스-성능핵심.md)). 분기는 부모 책임.

## 자가 점검
- 빌드 통과?
- 멀티데이만 있는 날 → 셀 안엔 텍스트 없고, 행 overlay 바만 가로지름?
- 멀티데이 + 단일 일이 같은 날 → 단일 일은 셀 안에, 멀티데이는 overlay 에?
- `+N` 계산이 멀티데이를 안 세니까 일시적으로 작아 보일 수 있음 (10 단계에서 합산으로 복구)
- 퀴즈: 셀 안에서 `if isMultiday(e) { skip }` 식으로 한 것과 부모에서 미리 거른 것의 **차이**는? `prefix(maxVisible)` 와의 상호작용?
