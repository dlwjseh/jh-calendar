# 단계 9: 셀 내부 컨텐츠 밀어내기 (멀티데이 lane 갯수만큼)

> 새 개념 없음. 부모(주 행) 가 계산한 **lane 갯수** 를 셀(`DayCellView`) 에 prop 으로 전달하고, 셀이 그만큼 상단 여백을 비운다.

## 작업 목표
지금까지 셀 내부 day 번호 텍스트 바로 아래에 단일 일 이벤트들이 붙어 있었다. 그러나 행 overlay 의 멀티데이 바도 같은 영역을 차지한다 → 두 레이어가 겹친다.

이번 단계: **그 주의 lane 갯수만큼** 셀 내부 컨텐츠를 아래로 밀어 멀티데이 바와 단일 일 이벤트가 **세로로 자연스럽게 늘어선** 모양으로.

## 사전 산출물
- 08 의 `let laneCount = (laned.map(\.lane).max() ?? -1) + 1` — 그 주의 lane 갯수.

## 작업 가이드

**1) `WeekRowView` → `DayCellView` 로 prop 전달**

```swift
WeekRowView(...) {
    HStack(spacing: 0) {
        ForEach(row) { cell in
            DayCellView(cell: cell,
                        events: eventsByDayIndex[...] ?? [],
                        multidayLaneCount: laneCount,   // ← 추가
                        onSelectDay: onSelectDay)
        }
    }
    .overlay { ... }
}
```

**2) `DayCellView` 가 lane 갯수만큼 상단 reserved space**

```swift
struct DayCellView: View {
    // ...
    let multidayLaneCount: Int     // ← 추가

    private let multidayBarHeight: CGFloat = 16   // 04~08 의 바 높이
    private let multidayBarGap: CGFloat = 2

    private var reservedTop: CGFloat {
        CGFloat(multidayLaneCount) * (multidayBarHeight + multidayBarGap)
    }

    var body: some View {
        VStack(spacing: 0) {
            Text("\(cell.day)")
                .font(.system(size: 12))
                // ...

            // 여기에 reserved space
            Spacer().frame(height: reservedTop)

            VStack(alignment: .leading, spacing: 2) {
                ForEach(events.prefix(maxVisible)) { e in
                    // 기존 단일 일 이벤트 렌더링
                }
                // +N
            }
            Spacer(minLength: 0)
        }
        // ...
    }
}
```

- **`Spacer().frame(height:)`** — 지정된 높이의 빈 공간. flexible spacer 와 달리 늘어나지 않음.
- 멀티데이 바와 셀 내부의 좌표가 같은 행 안에서 일관되게 정렬되도록 **베이스 y 값(`barFrame` 호출부의 `y: 24`) 과 reserved space 의 시작점이 동일** 해야 한다. 즉 `Text("\(cell.day)")` + `padding(.bottom, 4)` 직후에 멀티데이 바가 시작.

**3) (선택) 멀티데이 베이스 y 정확히 맞추기**

만약 `Text("\(cell.day)")` 영역의 실제 높이가 폰트/패딩에 따라 다르다면, 08 의 `.offset(y: 24)` 값과 셀 내부 day 텍스트 아래까지의 실제 거리가 어긋날 수 있음. 두 방법:

- (a) 둘 다 **상수로 통일**: 셀의 day 텍스트 영역을 `.frame(height:)` 로 고정, overlay 의 `.offset(y:)` 도 같은 상수 사용.
- (b) **PreferenceKey** 로 day 텍스트 영역 높이를 측정해 상위로 올린 후 overlay 가 받아 씀. 더 정확하지만 복잡.

이번 범위에선 (a) 가 단순. 추후 폰트 크기 바뀌면 한 곳에서 갱신.

## 직접 구현하기
- [ ] `DayCellView` 에 `multidayLaneCount: Int` prop 추가
- [ ] day 번호 아래에 `Spacer().frame(height: reservedTop)` 삽입
- [ ] `WeekRowView` 에서 `laneCount` 계산해 `DayCellView` 에 전달
- [ ] 멀티데이 0/1/2 lane 케이스 시각 확인 — 단일 일 이벤트가 바 아래로 자연스럽게 위치
- [ ] lane 갯수가 0 인 주 → 셀 내부 컨텐츠 위치가 기존과 같은지 (회귀 없음)

## 자가 점검
- 빌드 통과?
- 멀티데이 0개 주 → 셀 내부 컨텐츠가 11번 단계와 동일 위치?
- 멀티데이 1개 주 → 단일 일 이벤트가 16+2px 아래로 내려가 있고, 그 빈 자리에 멀티데이 바가 정확히 들어가 있는지?
- 멀티데이 2~3개 주 → lane 갯수만큼 비례해 내려가는지?
- 퀴즈: lane 갯수를 셀이 아니라 **행 단위 환경값**으로 (예: `.environment` 또는 PreferenceKey) 내려보내는 게 더 깔끔한가? 트레이드오프?

## Claude 리뷰 체크리스트
- [ ] `reservedTop` 계산이 한 곳(`multidayBarHeight`, `multidayBarGap` 상수) — 매직 넘버 분산 X
- [ ] lane 갯수 0 일 때 reserved 가 0 → 회귀 없음
- [ ] overlay 의 `y: 24` 와 셀 내부의 day 텍스트 영역 높이가 동기화됨
