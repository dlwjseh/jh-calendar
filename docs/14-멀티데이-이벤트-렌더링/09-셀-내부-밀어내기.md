# 단계 9: 셀 내부 컨텐츠 밀어내기 (셀별 lane 갯수만큼)

> 새 개념: **`DateInterval` 의 closed-interval 함정과 half-open 직접 비교**. 그 외엔 이전 단계 조합.

## 작업 목표
지금까지 셀 내부 day 번호 텍스트 바로 아래에 단일 일 이벤트들이 붙어 있었다. 그러나 행 overlay 의 멀티데이 바도 같은 영역을 차지한다 → 두 레이어가 겹친다.

이번 단계: **각 셀을 지나가는 멀티데이 lane 수** 만큼 셀 내부 컨텐츠를 아래로 밀어, 멀티데이 바와 단일 일 이벤트가 **세로로 자연스럽게 늘어선** 모양으로.

> 디자인 선택: **셀별 컴팩트**. 같은 주에 멀티데이가 있어도, 그 바가 지나가지 **않는** 셀은 day 번호 바로 아래부터 단일 일 이벤트를 시작한다 (= 빈 공간 reserved X). 표준 캘린더(Google/Apple)는 **행 단위 정렬**(주 max lane 으로 모든 셀 통일)이지만, 이 프로젝트는 셀 단위로 컴팩트하게 간다.

## 사전 산출물
- 08 의 `assignLanes` → `[(event, interval, lane)]`
- 멀티데이 바는 행 overlay 에서 `y: 24 + lane * (16 + 2)` 의 절대 좌표로 그려짐 (셀별 reserved 와 무관하게 행 좌표 고정)

## Swift / SwiftUI 개념

### `DateInterval` 은 **closed interval** — 끝점이 닿는 두 구간도 "교차" 로 판정

Apple docs: *"DateInterval represents a closed date interval in the form of [startDate, endDate]."*

→ `DateInterval.intersects(_:)` 와 `intersection(with:)` 모두 **closed** 기준. 끝점 한 점만 닿아도 true / non-nil.

```swift
let day = DateInterval(start: cal.startOfDay(for: cell.date), duration: 86400)
//                                                            ^^^^^ Mar 6 00:00 포함
let bar = DateInterval(start: mar6_00, ...)
day.intersects(bar)   // true  ← Mar 6 00:00 한 점에서 닿음. 의도와 다름.
```

**왜 함정인가**: 우리가 원하는 건 *"이 셀(=하루)의 어느 시점이 바와 실제로 겹치나"*. 셀 끝점(다음 날 00:00) 은 이 셀의 마지막 순간이 아니라 **다음 셀의 시작 순간**. 그래서 끝점 닿음은 "겹침" 으로 안 쳐야 함 → **half-open `[start, end)`** 의미가 필요.

**해결: 직접 비교**

```swift
let dayStart = cal.startOfDay(for: date)
let nextDayStart = cal.date(byAdding: .day, value: 1, to: dayStart)!
let overlaps = (bar.start < nextDayStart) && (bar.end > dayStart)
//                    ^                              ^
//              strict — 끝점 한 점 닿음 제외
```

- Java `java.time` 에서 `LocalDate` 비교 패턴 (`start <= x < end`) 과 동일 발상
- SQL `BETWEEN` 은 closed → DateInterval 과 닮음. 라이브러리마다 다르니 매번 확인 필요
- `cal.date(byAdding: .day, value: 1, ...)` 는 DST 안전 (`duration: 86400` 은 DST 일에 어긋날 수 있음)

## 작업 가이드

**1) `WeekRowView` — 주 단위 `laneCount` 를 **셀별** 계산으로 교체**

현재 (행 단위):
```swift
let laned = assignLanes(slices)
let laneCount = (laned.map(\.lane).max() ?? -1) + 1   // ← 주 전체
// ...
DayCellView(..., multidayLaneCount: laneCount, ...)   // 모든 셀에 같은 값
```

변경 (셀별, half-open 직접 비교):
```swift
let laned = assignLanes(slices)

// 헬퍼: 특정 날짜를 지나가는 lane 들의 max + 1
func laneCount(for date: Date) -> Int {
    let dayStart = cal.startOfDay(for: date)
    let nextDayStart = cal.date(byAdding: .day, value: 1, to: dayStart)!
    let lanes = laned.compactMap { l in
        (l.interval.start < nextDayStart && l.interval.end > dayStart) ? l.lane : nil
    }
    return (lanes.max() ?? -1) + 1
}

ForEach(row) { cell in
    DayCellView(...,
                multidayLaneCount: laneCount(for: cell.date),  // ← 셀마다 다른 값
                ...)
}
```

- `compactMap` 으로 "겹치면 lane, 아니면 nil" 후 nil 제거 → lane 들의 배열.
- `.max() ?? -1) + 1` 패턴은 08 의 주 단위 계산과 동일 — 비어있으면 0.
- ⚠️ 초기 구현에서 `DateInterval.intersects` 로 만들었더니 **다음날의 lane 까지 잡혀버림** — closed interval 함정. 위 "Swift / SwiftUI 개념" 참고.

> **왜 `lanes.count` 가 아니라 `max + 1` 인가?**
> 이 셀에 lane 2 짜리 바만 걸쳐있다면, 그 바가 행 좌표 `y = 24 + 2*18 = 60` 에 그려진다. 셀의 단일 일 이벤트는 그 아래(`y >= 78`)에서 시작해야 lane 2 바와 안 겹침. 즉 reserved 는 **자기 셀의 max lane + 1** 만큼 필요. (lane 0, 1 슬롯은 이 셀에선 비어있지만 공간은 차지)

**2) `DayCellView` — `Spacer().frame(height:)` 로 reserved top**

```swift
struct DayCellView: View {
    // ...
    let multidayLaneCount: Int   // 이미 prop 추가됨

    private let multidayBarHeight: CGFloat = 16
    private let multidayBarGap: CGFloat = 2

    private var reservedTop: CGFloat {
        CGFloat(multidayLaneCount) * (multidayBarHeight + multidayBarGap)
    }

    var body: some View {
        VStack(spacing: 0) {
            Text("\(cell.day)")
                .font(.system(size: 12))
                // ...
                .padding(.bottom, 4)

            Spacer().frame(height: reservedTop)   // ← lane 갯수 0이면 0px

            VStack(alignment: .leading, spacing: 2) {
                ForEach(events.prefix(maxVisible)) { e in
                    // 기존 단일 일 이벤트 렌더링
                }
                // +N
            }
            Spacer(minLength: 0)
        }
        // ...
    }
}
```

- **`Spacer().frame(height:)`** — 지정 높이 빈 공간. flexible spacer 와 달리 늘어나지 않음.
- `multidayLaneCount == 0` 이면 reserved 0 → 멀티데이 없는 셀은 기존(11번 단계)과 동일 위치에서 단일 일 이벤트 시작.

**3) 멀티데이 베이스 y 와 셀 day 영역 높이 동기화**

`WeekRowView.swift:75` 의 `.offset(y: 24 + ...)` 의 `24` 가 셀의 "day 번호 + `.padding(.bottom, 4)`" 영역 높이와 일치해야 lane 0 바가 day 텍스트 바로 아래에 정확히 들어감.

폰트 12, 시스템 line height + padding 4 + 셀 외곽 `.padding(.top, 6)` 까지 합쳐 24 근처. 정확한 정렬이 어긋나면 상수만 한 곳에서 조정.

## 조금 더 (선택)
- 행 정렬 vs 셀 컴팩트 의 트레이드오프 — Apple/Google 은 행 정렬을 택하는데 우리가 셀 컴팩트를 택한 이유: 빈 공간 비효율 < 일관 정렬. 사용해보고 어색하면 한 곳(주 단위 max) 으로 되돌릴 수 있음.
- `laneCount(for:)` 를 셀 7개에 매번 호출 = O(7 * laned.count). 셀 수가 7로 고정이라 무시 가능. 굳이 최적화한다면 `[Date: Int]` 사전 1회 계산.
- 디자인 정책: lane 갯수 상한(예: max 2 lane) → 그 이상 "+N more" (08 의 "조금 더"). 10 의 합산과 함께 다루면 자연스러움.
