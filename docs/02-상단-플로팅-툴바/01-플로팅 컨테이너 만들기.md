# 단계 1: 플로팅 컨테이너 만들기

## 학습 목표
- `HStack` 으로 자식들을 가로로 배치하는 감 잡기.
- `.background`, `.clipShape(Capsule())`, `.shadow` 를 조합해 macOS 스타일의 **캡슐(pill) + 그림자** floating 영역 만들기.
- 기존 `ZStack(alignment: .topLeading)` 위에 floating 레이어 한 층을 더 얹는 사고 방식.

## 사전 지식
- 기능 01 의 결과물 + 프로젝트 구조 정리 후, `ContentView` 는 다음 모양이다.
  ```swift
  // JHCalendar/ContentView.swift
  struct ContentView: View {
      var body: some View {
          ZStack(alignment: .topLeading) {
              Color.clear.frame(minWidth: 900, minHeight: 600)  // (1) 컨테이너
              TrafficLightHoverArea()                           // (2) 호버 영역 (별도 컴포넌트)
          }
          .ignoresSafeArea()
      }
  }
  ```
- 트래픽라이트 호버 로직은 `JHCalendar/Features/TitleBar/TrafficLightHoverArea.swift` + `TrafficLightController.swift` 로 분리돼 있다 — 이 단계에서 건드릴 일은 없다.
- 트래픽라이트 버튼은 좌상단 ~100×40 영역에 호버 시 페이드 인 된다.

## Swift / SwiftUI 개념

### 1) HStack — 가로 stack

SwiftUI 의 layout 은 stack 3종세트로 시작된다.

| Stack | 방향 |
|---|---|
| `HStack` | 가로 (자식을 좌→우) |
| `VStack` | 세로 (자식을 상→하) |
| `ZStack` | 겹침 (뒤에 쓴 자식이 앞쪽) |

Vue / CSS 비유: `display: flex; flex-direction: row` 를 컴포넌트로 직접 쓰는 감각.

```swift
HStack(spacing: 8) {
    Color.red.frame(width: 24, height: 24)
    Color.blue.frame(width: 24, height: 24)
}
```

`spacing:` 은 자식 사이 간격. 기본값은 시스템 기본 spacing.

### 2) `.background` 와 `.clipShape` — 순서가 중요하다

```swift
SomeView()
    .background(Color.white)              // ① 뒤에 흰 배경
    .clipShape(Capsule())                 // ② 배경 포함 캡슐 모양으로 잘라냄
```

- `.background` 는 "현재 view 의 뒤에 다른 view 를 깔아준다"
- `.clipShape` 는 "현재 view 를 도형 모양으로 잘라낸다"

Vue / CSS 비유: `background-color` + `border-radius: 9999px` + `overflow: hidden` 의 묶음. 단 SwiftUI 는 modifier 가 **순서대로 view 를 한 겹씩 감싸기** 때문에 순서를 바꾸면 결과가 다르다.

> 자문자답거리: `.clipShape` 를 먼저 하고 `.background` 를 나중에 하면? → 콘텐츠는 캡슐 모양으로 잘렸지만 배경은 그대로 사각형으로 깔린다 → 모서리 밖으로 배경이 삐져나온다.

### 2-1) Capsule shape

`Capsule()` 은 SwiftUI 의 내장 shape 중 하나로, **양 끝이 반원인 알약(pill) 모양** 이다.
- 사실상 `RoundedRectangle(cornerRadius: min(width, height) / 2)` 와 같다.
- 가로가 세로보다 길면 → 양옆 끝이 반원
- 정사각형이면 → 원

```swift
.clipShape(Capsule())
.clipShape(RoundedRectangle(cornerRadius: 10))   // 비교용 — 단순 둥근 사각형
```

> macOS 의 시스템 toolbar/badge UI 에 자주 쓰이는 shape — Apple Calendar/Notes 의 "오늘" 배지나 floating 컨트롤들이 다 이 모양.

### 3) `.shadow`

```swift
.shadow(color: .black.opacity(0.15), radius: 8, x: 0, y: 2)
```

- `radius` — 흐림 반경 (클수록 부드럽고 멀리 퍼짐)
- `x`, `y` — 그림자 오프셋
- CSS `box-shadow` 와 거의 같다.

floating 카드는 보통 `radius: 6~10`, `opacity: 0.1~0.2`, `y: 1~3` 정도가 자연스럽다. 너무 진하면 무거워 보인다.

### 4) ZStack 의 stacking 순서

ZStack 은 **나중에 선언된 자식이 앞쪽에 그려진다**. 우리 floating 카드는 호버 영역 위에 떠야 시각적으로 자연스럽고, 클릭/호버 충돌도 없다 — 그래서 ZStack 의 **세 번째(마지막) 자식**으로 추가한다.

### 5) 위치 잡기 — `.padding(.top, ...)` / `.padding(.leading, ...)`

ZStack 의 alignment 가 `.topLeading` 이라 자식은 기본적으로 좌상단 (0,0) 에 붙는다. 거기서 안쪽으로 띄우려면 `.padding(.top, _)` `.padding(.leading, _)` 을 쓴다.

> 트래픽라이트 자리: 좌상단에 약 70~80pt 정도의 여유를 둬야 호버 시 나타난 빨/노/초 버튼과 겹치지 않는다.

### `FloatingToolbar.swift` 골격

단계 1 에서는 placeholder (회색 박스) 2개로 비워두고, 실제 버튼은 단계 2 에서 채운다.

```swift
// JHCalendar/Features/FloatingToolbar/FloatingToolbar.swift
import SwiftUI

struct FloatingToolbar: View {
    var body: some View {
        HStack(spacing: 4) {
            // placeholder (단계 2 에서 진짜 Button 으로 교체)
            Color.gray.opacity(0.3).frame(width: 28, height: 28)
            Color.gray.opacity(0.3).frame(width: 28, height: 28)
        }
        .padding(.horizontal, 8)
        .padding(.vertical, 4)
        .background(/* TODO: 배경색 */)
        .clipShape(/* TODO: Capsule */)
        .shadow(/* TODO */)
        .padding(.top, /* TODO */)
        .padding(.leading, /* TODO */)
    }
}
```

### `ContentView.swift` 수정

```swift
ZStack(alignment: .topLeading) {
    Color.clear
        .frame(minWidth: 900, minHeight: 600)

    TrafficLightHoverArea()

    FloatingToolbar()    // ▼ 새로 추가
}
```

힌트:
- 배경색은 일단 **단색**으로 시작. 다음 단계에서 `Material` 로 바꾸기 좋게:
  - `Color.white` (라이트 모드만 고려) 또는
  - `Color(NSColor.controlBackgroundColor)` (시스템 적응형 단색)
- `Capsule()` 은 인자가 필요 없다 — `cornerRadius` 자체가 height 의 절반으로 자동 계산됨.
- HStack 의 padding 은 가로/세로를 다르게 — 가로는 좀 넉넉하게(8pt~), 세로는 짧게(4pt~) 하면 캡슐의 가로로 긴 비율이 자연스럽다.
- 좌측 padding 은 80pt 안팎 — 호버 시 나타나는 트래픽라이트와 겹치지 않게.
- 상단 padding 은 8~12pt — 윈도우 모서리에 너무 붙지 않게.

## 조금 더 (선택)
- `.background(_:in:)` 라는 오버로드: 한 줄로 "어떤 도형 모양의 배경" 을 깔 수 있다.
  ```swift
  .background(.white, in: RoundedRectangle(cornerRadius: 10))
  ```
  단계 3 이후에 더 짧게 줄이고 싶으면 시도.
- modifier 순서가 결과를 바꾸는 이유: SwiftUI 의 modifier 는 "이전 view 를 감싸는 새 view" 를 반환한다 (양파 껍질 모델). Stream API 의 중간 연산이 새 Stream 을 반환하는 것과 같은 발상.
