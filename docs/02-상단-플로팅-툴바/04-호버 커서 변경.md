# 단계 4: 버튼 호버 시 손모양 커서

## 학습 목표
- macOS 14 의 SwiftUI 만으로는 커서를 직접 바꿀 수 없다는 점을 이해.
- `.onHover` modifier 로 hover 진입/이탈을 감지.
- AppKit 의 `NSCursor` 를 SwiftUI 와 연결.
- View extension 으로 재사용 가능한 modifier (`view.pointerCursor()`) 만들기.

## 사전 지식
- 단계 1~3 완료: floating 카드(Material 배경) 안에 사이드바 / `+` 두 Button 이 있는 상태.
- AppKit 호출 경험: 기능 01 의 `TrafficLightController.swift` 에서 `NSWindow` 를 만진 적이 있음 — 이번에도 같은 결의 "SwiftUI 가 못 가리는 macOS API 를 AppKit 으로 끼워넣기" 패턴.

## Swift / SwiftUI 개념

### 1) macOS 14 의 SwiftUI 에는 cursor modifier 가 없다

웹에서는 `cursor: pointer` 한 줄, Vue 에서도 `style="cursor: pointer"` 한 줄이면 끝이다. SwiftUI 는 iOS/macOS 공용이고 iOS 는 커서 개념 자체가 없어서 — macOS 전용인 cursor 가 SwiftUI 표준 modifier 에는 빠져 있다.

(macOS 15+ 부터 `.pointerStyle(.link)` 가 새로 생겼지만 우리 타깃은 macOS 14+ 라 AppKit 으로 간다.)

### 2) `.onHover { hovering in ... }`

view 위에 마우스가 들어오면 `true`, 나가면 `false` 콜백. 기능 01 단계 1 에서 이미 사용한 그 모양.

```swift
SomeView()
    .onHover { hovering in
        // hovering: Bool
    }
```

### 3) `NSCursor` — push / pop / set

macOS 의 모든 시스템 커서가 이 클래스의 static 프로퍼티에 있다.

- `NSCursor.pointingHand` ← 이번에 쓸 손모양
- `NSCursor.arrow` ← 기본 화살표
- `NSCursor.iBeam`, `.crosshair`, `.resizeLeftRight` …

호출 방식 세 가지:

```swift
NSCursor.pointingHand.push()   // 스택에 새 커서 푸시
NSCursor.pop()                 // 가장 최근에 푸시된 것 제거 → 이전 커서로 복귀
NSCursor.pointingHand.set()    // 스택 무관, 그냥 현재 커서를 그것으로 변경
```

`.onHover` 처럼 enter/exit 가 짝이 잘 맞는 곳에선 push/pop 이 자연스럽다. 짝이 깨질 수 있는 상황(다른 영역으로 빠르게 빠져나가거나 view 가 사라지는 경우)에선 `.set()` 이 안전.

### 4) View extension 으로 재사용

두 Button 마다 `.onHover { ... NSCursor ... }` 를 두 번 박는 건 중복이다. SwiftUI 의 modifier 는 결국 `View` 가 가진 메서드이므로, **우리가 직접 메서드를 추가**할 수 있다.

```swift
extension View {
    func pointerCursor() -> some View {
        // TODO: 본문은 구현 가이드에서
    }
}
```

> Java 비유: 클래스 본체를 건드리지 않고 외부에서 메서드를 덧붙이는 형태. Java 만 보면 "Utils 클래스의 static helper" 와 비슷하지만, 호출이 `Utils.pointerCursor(view)` 가 아니라 `view.pointerCursor()` 로 자연스럽게 체이닝된다는 점이 다르다.

`some View` 의 `some` 은 **opaque return type**. "정확한 타입은 컴파일러가 알지만 외부에는 그냥 '어떤 View' 라고만 알린다" 는 뜻 — SwiftUI 의 modifier 들이 모두 이 패턴을 쓴다.

### 5) 어디에 적용할까

- **각 Button 에 따로** — 버튼 hit area 안에서만 손모양. 가장 정확.
- **두 버튼을 감싸는 HStack 에 한 번** — 코드는 짧아지지만 버튼 사이 spacing 위에서도 손모양이 됨.

이번엔 (a) "각 Button 에 따로" 권장. 보통 카드 패딩 영역까지 손모양이 되는 건 어색하다.

## 조금 더 (선택)
- **macOS 15+** 라면 `.pointerStyle(.link)` 한 줄이면 AppKit 없이 끝. 같은 일을 SwiftUI 표준으로.
- **다른 NSCursor**: `.iBeam` (텍스트), `.crosshair` (정밀 클릭), `.resizeLeftRight`, `.openHand` / `.closedHand` (드래그 중 표현), `.operationNotAllowed` (금지 표시). 호버 영역마다 의미에 맞는 커서를 쓰면 native 한 느낌이 산다.
- **ButtonStyle** 프로토콜을 직접 구현하면 hover state, pressed state, cursor 변경을 한 곳에 묶을 수도 있다. 다음 단계(05) 에선 좀 더 가벼운 방식 — `IconButton` 이라는 작은 뷰로 분리하면서 hover 배경을 추가 — 으로 가고, ButtonStyle 방식은 거기서 "조금 더" 도전 과제로 남긴다.
- **`.help("새 일정 추가")`** 한 줄을 같이 붙이면 hover 시 시스템 tooltip 도 같이 뜬다 — 손모양 + tooltip 조합이 macOS 표준 UX.
