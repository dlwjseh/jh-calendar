## Swift 개념

### raw value enum (`enum X: String`)
10단계의 `EventDialogMode` 는 **연관값(associated value)** enum 이었다 — 케이스마다 다른 데이터를 품는다. 이번엔 **raw value** enum — 각 케이스가 고정된 "원시값"(String/Int 등)에 1:1로 매핑된다.

```swift
enum RecurrenceRule: String, Codable, CaseIterable {
    case none, daily, weekly, monthly, yearly
}
```

- `: String` → 각 케이스의 raw value 는 케이스 이름 문자열(`"none"`, `"daily"` …). `RecurrenceRule(rawValue: "daily")` 로 역변환, `.daily.rawValue` 로 문자열.
- **Java 비교**: Java enum 은 그 자체가 완전한 클래스(필드·메서드 가능). Swift 의 raw value enum 은 그보다 가벼워서, Java 의 `name()` / `valueOf(String)` 에 해당하는 매핑을 **언어가 공짜로** 준다. (Swift enum 도 메서드/연산프로퍼티는 가질 수 있다 — 03단계에서 라벨 메서드를 붙일 것.)

### `CaseIterable`
`CaseIterable` 채택 → `RecurrenceRule.allCases` 가 `[.none, .daily, .weekly, .monthly, .yearly]` 배열로 **자동 생성**된다. 03단계 피커에서 옵션 목록으로 그대로 쓴다. (Java 의 `values()` 와 같은 결.)

### `Codable`
JSON 직렬화 호환용. raw value enum 은 어차피 자동 Codable 이지만 명시해 두면 의도가 분명. (18단계 `Codable` 와 동일 개념.)

### SwiftData 가 enum 을 저장하는 법
SwiftData 는 **`RawRepresentable` 이고 raw type 이 저장 가능 타입(String/Int 등)** 인 enum 을 `@Model` 프로퍼티로 **그냥** 받는다. 별도 변환기 필요 없음 — 내부적으로 raw value(String)로 컬럼에 저장.

```swift
@Model
final class Event {
    // ...기존 필드...
    var recurrence: RecurrenceRule = RecurrenceRule.none   // ← 추가. @Model 은 fully-qualified 기본값 요구
}
```

> **함정 ① — `@Model` 기본값은 fully-qualified**: 위에서 `= .none` (암시적 멤버) 으로 쓰면 *"A default value requires a fully qualified domain named value (from macro 'Model')"* 컴파일 에러가 난다. `@Model` 매크로가 코드를 재생성할 때 `.none` 의 타입 문맥이 사라지기 때문. → 프로퍼티 기본값은 `RecurrenceRule.none` 으로 타입을 붙인다. (단, `init` 파라미터 기본값은 일반 함수라 `.none` 그대로 OK.)

> **함정 ② — 마이그레이션 (실측, 문서 초안과 다름)**: 이미 디스크에 저장된 기존 이벤트들은 `recurrence` 컬럼이 없다. **이론**상 기본값을 주면 lightweight migration 이 기존 행을 채워줘야 하지만, **실제로 SwiftData 의 자동 마이그레이션은 커스텀 enum(RawRepresentable)의 기본값을 *기존 행*에 backfill 해주지 못한다.** 옛 행 컬럼이 NULL 로 남아, 로드 시 `Could not cast value of type 'Optional<Any>' to 'RecurrenceRule'` 로 **런타임 크래시**한다 (빌드는 통과 — 실행 중 기존 데이터 읽을 때 터짐).
>
> **해결** (dev 학습 앱 기준):
> - (간단) 로컬 스토어 리셋 — `~/Library/Containers/com.jh.JHCalendar/Data/Library/Application Support/default.store*` 삭제 후 재실행 → 새 스키마로 재생성.
> - (데이터 보존) SwiftData 스토어 = SQLite 이므로 직접 backfill: `UPDATE ZEVENT SET ZRECURRENCE = 'none' WHERE ZRECURRENCE IS NULL;` (enum 은 raw string 으로 `ZRECURRENCE VARCHAR` 컬럼에 저장됨 — DataGrip/`sqlite3` 등으로. **앱 종료 후** 실행.)
> - (정석) `VersionedSchema` + `SchemaMigrationPlan` — 이번 범위 밖.
>
> **Java 비유**: 기존 테이블에 `NOT NULL` 컬럼을 DEFAULT backfill(Flyway) 없이 추가하면, 새 INSERT 는 되지만 옛 행을 `@Column(nullable=false)` 로 로드할 때 깨지는 것과 같다. JPA `ddl-auto` 가 컬럼을 *추가*는 해도 기존 행 값까지 채워주진 않는 것과 닮음.

## 구현 가이드
- `RecurrenceRule.swift` 새 파일(`Features/Event/`) 또는 `EventModels.swift` 안에 enum 정의.
- `Event` 에 `var recurrence: RecurrenceRule = RecurrenceRule.none` 추가 (프로퍼티 기본값은 fully-qualified — 위 함정 ① 참고).
- `Event.init(...)` 에 `recurrence: RecurrenceRule = .none` 파라미터 추가 (기본값 줘서 기존 호출부 안 깨지게).

```swift
init(name: String, isAllDay: Bool, category: Category? = nil,
     startDate: Date, endDate: Date,
     recurrence: RecurrenceRule = .none) {   // ← 추가
    // ...
    self.recurrence = recurrence
}
```
