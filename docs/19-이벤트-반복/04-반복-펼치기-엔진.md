# 단계 4: 반복 펼치기(expansion) 엔진 + 렌더링

> 이 기능의 **핵심**. 저장은 1건인데 화면엔 여러 날 — 그 "펼치기" 를 만든다.

## 학습 목표
- 보이는 그리드 범위(`gridInterval`)에 대해 반복 이벤트의 **occurrence 날짜들**을 생성하는 `RecurrenceExpander` 를 만든다.
- `#Predicate` 로는 왜 반복 매칭이 안 되는지 이해하고, 매칭을 **인메모리**로 옮긴다.
- 달력 셀(`MonthlyCalendarView`)과 일 팝업(`DayPopupDialog`)이 펼쳐진 occurrence 를 표시하게 한다.

## 사전 산출물
- 03단계까지: `Event.recurrence` 가 저장되고, 다이얼로그에서 선택 가능.
- `CalendarStore.gridInterval` (16단계) — 현재 화면 6주 범위의 `DateInterval`.
- `@Query` + `#Predicate` (11·12단계).

## Swift / SwiftUI 개념

### 왜 `#Predicate` 로는 안 되나
`#Predicate` 는 SwiftData 가 **SQL 로 번역**해서 DB 에서 거른다. 그래서 표현식 안에서 `Calendar` 계산("이 규칙이 이 날짜에 맞나", "요일이 같나")을 **쓸 수 없다** — 단순 비교(`startDate < x`)만 가능.

→ 반복 매칭은 DB 가 아니라 **메모리에서** 한다. `#Predicate` 는 후보를 좁히는 용도(예: `startDate <= 범위끝`)로만 쓰고, "이 날 발생?" 정밀 판정은 Swift 코드로.

> Spring Data 로 치면, 복잡한 도메인 규칙을 JPQL 한 방에 못 짜서 후보만 쿼리로 줄이고 자바 스트림에서 거르는 상황과 같다.

### "가상 인스턴스" — 저장 1건 → 화면 N개
반복 이벤트를 occurrence 마다 `Event` 행으로 **저장하면 안 된다** (무한·중복·수정지옥). 대신 **렌더링용 경량 표현**을 그때그때 만든다.

```swift
struct EventOccurrence: Identifiable {
    let event: Event   // 원본 (저장된 1건)
    let date: Date     // 이 occurrence 가 놓일 날
    var id: ... 
}
```
- SwiftData 에 `insert` 금지. 화면용 struct 일 뿐.
- 클릭 시엔 `occurrence.event`(원본)를 넘겨 수정 → **전체 시리즈에 반영**(v1 의도).

### 보이는 범위만 펼치므로 무한이어도 안전
무한 반복이라도 펼치는 대상은 `gridInterval`(약 42일)뿐. 그래서 종료일 없이도 루프가 유한하다. 이게 "끝 처리 미뤄도 OK" 의 근거.

## 구현 가이드

### 1) Expander
`Features/Event/RecurrenceExpander.swift` 새 파일.

```swift
enum RecurrenceExpander {
    /// event 가 interval 안에서 발생하는 날짜들 (시작일 0시 기준)
    static func occurrences(of event: Event, in interval: DateInterval) -> [Date] {
        let cal = Calendar.current
        let start = cal.startOfDay(for: event.startDate)
        // 원래 시작일 이전엔 발생 없음
        switch event.recurrence {
        case .none:
            return interval.contains(start) ? [start] : []
        case .daily:
            // start 부터 하루씩, interval 안인 날 모으기
            // TODO
        case .weekly:
            // 같은 요일만 (cal.component(.weekday))
            // TODO
        case .monthly:
            // 같은 일(day-of-month). 그 달에 그 일이 없으면 skip (예: 31일)
            // TODO
        case .yearly:
            // 같은 월+일. 2/29 는 평년 skip
            // TODO
        }
    }

    /// 단일 날짜 판정 (팝업용)
    static func occurs(_ event: Event, on day: Date) -> Bool {
        let d = Calendar.current.startOfDay(for: day)
        return occurrences(of: event, in: DateInterval(start: d, duration: 1)).contains(d)
    }
}
```

힌트:
- 날짜 순회는 `cal.date(byAdding: .day, value: 1, to:)` 로 stride 하거나, 더 깔끔하게 `cal.enumerateDates(startingAfter:matching:matchingPolicy:)` 사용.
- weekly: `cal.component(.weekday, from: start)` 와 후보 날의 weekday 비교.
- monthly/yearly 의 "없는 날(31일, 2/29)" 은 `matchingPolicy: .strict` 로 enumerateDates 가 자동으로 건너뛰게 하거나, `DateComponents` 로 만든 날짜가 nil/다른 달로 튀는지 체크.
- 모든 occurrence 는 `>= start` 이고 `interval.contains` 인 것만.

### 2) 달력 셀 렌더링 (`MonthlyCalendarView`)
현재 `events` 는 `gridInterval.contains($0.startDate)` 로 거르고 `singleDayEventsByDayIndex`(날짜→이벤트 배열)를 만든다 — 이게 **원래 날짜 하나만** 본다.

바꿀 방향:
- non-recurring 이벤트는 기존 로직 유지.
- recurring 이벤트는 `RecurrenceExpander.occurrences(of:in: store.gridInterval)` 로 날짜들을 받아, **그 날짜마다** 해당 이벤트를 day-index 맵에 넣는다.
- `DayCellView` 는 결국 "이 날 보여줄 이벤트 목록" 만 받으므로, **맵을 채우는 쪽**(`eventsByDay`)만 occurrence 를 반영하면 셀 코드는 거의 안 건드려도 된다.

> 멀티데이는 이번 범위 밖 — expander 는 단일/종일만 다룬다. recurring 인데 멀티데이인 경우는 펼치지 말고 원래 동작(또는 첫 날만)으로 둔다. 단순화.

### 3) 일 팝업 (`DayPopupDialog`)
현재 `#Predicate` 로 그 날 겹치는 이벤트를 가져오는데, 반복 이벤트는 원래 날짜에만 걸려 안 잡힌다.

바꿀 방향(둘 중 하나):
- (a) `@Query` 를 넓혀(또는 `#Predicate` 를 `startDate <= dayEnd` 로 완화) 후보를 가져온 뒤, `RecurrenceExpander.occurs(event, on: date)` 로 메모리 필터.
- (b) non-recurring 은 기존 predicate, recurring 은 별도 처리.

→ (a) 가 단순. "그 날 직접 걸린 이벤트" + "그 날 occurrence 가 있는 반복 이벤트" 를 합쳐 표시.

## 자가 점검
- 빌드 통과?
- 5/28(목) "매주 목요일" 이벤트 → 그 달 **모든 목요일** 셀에 표시? 다음 달로 이동해도?
- "매월 28일" → 매달 28일에? "매년 5월 28일" → 5월에만?
- "매일" → 범위 내 모든 날?
- 31일 "매월" 이벤트 → 31일 없는 달(2·4·6·9·11월)은 건너뛰는가?
- 반복 이벤트의 occurrence 를 클릭 → 수정 다이얼로그가 원본을 열고, 저장하면 전 시리즈에 반영되는가? (시작일이 원본 날짜로 보이는 건 알려진 거친 부분 — 후속에서 "이 날짜만" 으로 개선)
- 퀴즈: 왜 occurrence 를 `Event` 로 저장하지 않고 struct 로 두는가? — 무한·중복·수정 동기화 문제. 저장은 규칙 1건이 진실의 원천(source of truth).
