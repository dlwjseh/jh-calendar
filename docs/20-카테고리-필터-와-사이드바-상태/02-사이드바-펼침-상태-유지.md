# 단계 2: 사이드바 펼침 상태 유지 (`@AppStorage`)

## 학습 목표
- 사이드바를 펼친(또는 닫은) 상태로 앱을 종료하면, 다시 켰을 때 **그 상태 그대로** 뜨게 한다.
- `@State`(메모리, 휘발) 와 `@AppStorage`(디스크, 영속)의 차이를 안다.

## 사전 지식
- `ContentView.isSidebarVisible`(7번 줄)가 사이드바 펼침 여부를 들고 있고, `FloatingToolbar` 의 토글 버튼이 이 바인딩(`$isSidebarVisible`)으로 켜고 끈다.
- 지금은 `@State private var isSidebarVisible = false` → **앱 실행마다 false(닫힘)로 초기화**된다.

## Swift / SwiftUI 개념

### `@AppStorage`
`UserDefaults`(앱 전용 키-값 저장소)에 자동으로 읽고 쓰는 SwiftUI 프로퍼티 래퍼다.

```swift
@AppStorage("isSidebarVisible") private var isSidebarVisible = false
//            └ 저장 키(문자열)                              └ 저장값 없을 때 기본값
```

- 값이 바뀌면 **자동으로 UserDefaults 에 저장**되고, 앱을 다시 켜면 그 키로 **읽어와 복원**한다.
- `@State` 처럼 SwiftUI 동적 프로퍼티라, 바뀌면 뷰가 다시 그려지고 `$isSidebarVisible` 바인딩도 그대로 쓸 수 있다.
- JS 비유: **`localStorage` 에 묶인 반응형 변수**. 읽으면 `localStorage.getItem`, 쓰면 `setItem` 이 자동으로 일어나는 셈. (Java 로 치면 작은 설정값을 `Preferences`/properties 파일에 자동 동기화.)
- 지원 타입은 `Bool`/`Int`/`String`/`Double` 등 기본형. 여기선 `Bool` 이라 그대로 OK.

> `@State` 는 뷰가 사라지면 사라지는 **메모리** 상태고, `@AppStorage` 는 앱을 꺼도 남는 **디스크** 상태다. "껐다 켜도 유지" 가 필요할 때만 후자를 쓴다.

## 구현 가이드
> 한 줄 교체에 가깝다. 직접 해볼 것.

- `ContentView` 의 `@State private var isSidebarVisible = false` 를 `@AppStorage(...)` 선언으로 바꾼다.
- 키 문자열은 다른 설정과 겹치지 않게 명확히 (예: `"isSidebarVisible"`).
- 토글 쪽(`FloatingToolbar` 로 넘기는 `$isSidebarVisible`)은 **건드릴 필요 없다** — `@AppStorage` 도 바인딩(`$`)을 제공한다.

생각해볼 점:
- 펼침 폭은 `.frame(width: isSidebarVisible ? 240 : 0)`(ContentView 21번 줄)로 이미 상태에 묶여 있다. 시작값이 복원되면 자동으로 맞는 폭으로 뜬다 — 추가 작업 불필요.

## 조금 더 (선택)
- `@AppStorage` 는 내부적으로 `UserDefaults.standard` 를 쓴다. 여러 키를 모아 관리하거나 기본값을 한곳에 두고 싶을 때 어떻게 구조화하는지 찾아보면 설정이 늘어날 때 도움이 된다.
- 창 크기·마지막 본 달 같은 다른 "앱 설정" 도 같은 패턴으로 영속화할 수 있다.
