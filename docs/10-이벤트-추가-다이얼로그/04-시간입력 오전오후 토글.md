# 단계 4: 시간 입력 — 오전/오후 토글 (focusable + onMoveCommand)

> 이벤트 다이얼로그에 들어갈 **커스텀 시간 입력기** 의 첫 조각.
> 기본 `DatePicker` 가 별로라 직접 만든다. 이번 단계는 **오전/오후 토글만** — 시·분은 다음 단계.

## 학습 목표
이 단계를 마치면:
- 입력 컨트롤이 아닌 **일반 `Text` 를 키보드 포커스 가능** 하게 만들 수 있다 (`.focusable()`).
- 포커스된 뷰에서 **↑/↓ 방향키를 가로채** 상태를 토글할 수 있다 (`.onMoveCommand`).
- **마우스 클릭으로도 포커스** 가 가게 연결할 수 있다.
- 결과물: 다이얼로그 안 "오전"/"오후" 글자를 클릭하면 포커스 링이 뜨고, ↑ 또는 ↓ 누르면 오전↔오후 토글.

## Swift / SwiftUI 개념 (이 단계에서 **새로** 배우는 것만)

### 1) `.focusable()` — 비입력 뷰를 포커스 대상으로 만들기

지금까지 `.focused($isNameFocused)` 가 **그냥 동작했던 이유**: `TextField`·`Toggle` 같은 입력 컨트롤은 원래부터 키보드 포커스를 받을 수 있는 뷰라서다. 반면 `Text` 는 그냥 글자 → **기본적으로 포커스 대상이 아니다.** 그래서 명시적으로 켜줘야 한다:

```swift
Text("오전")
    .focusable()        // 이제 Tab / 클릭으로 포커스 받을 수 있음
```

> **Vue/JS 비유**: `<span>` 은 원래 `Tab` 으로 포커스가 안 가지만 `tabindex="0"` 을 주면 포커스 대상이 된다. `.focusable()` 이 딱 그 `tabindex="0"` 역할이다. (`TextField` 는 `<input>` 처럼 기본 포커스 가능.)

`.focusable()` 한 뷰는 `@FocusState` + `.focused($binding)` 로 08 에서 배운 방식 그대로 포커스 상태를 읽고/줄 수 있다 — **여기서 `@FocusState` 자체는 새 개념이 아니다.** 새로운 건 "입력 컨트롤이 아닌 뷰도 `.focusable()` 만 붙이면 같은 메커니즘에 합류한다" 는 점.

### 2) `.onMoveCommand(perform:)` — 방향키 = "이동 명령"

macOS 에서 포커스된 뷰는 화살표 키를 **"이동 명령(move command)"** 이라는 의미 단위로 받을 수 있다. SwiftUI 가 키코드 파싱을 대신 해주고, 우리는 방향만 받는다:

```swift
.onMoveCommand { direction in
    // direction: .up / .down / .left / .right
    switch direction {
    case .up, .down:
        // TODO: 오전 ↔ 오후 토글
    default:
        break
    }
}
```

- **포커스됐을 때만** 호출된다. 포커스 안 된 상태에서 화살표를 눌러도 이 클로저는 안 옴 → 그래서 1) 의 `.focusable()` + 포커스가 선행 조건.
- `MoveCommandDirection` 은 `.up .down .left .right` 네 케이스 enum.

> **Vue/JS 비유**: `@keydown.up="..."` / `@keydown.down="..."` 와 같은 자리. 다만 JS 는 `event.key === 'ArrowUp'` 처럼 **물리 키** 를 보는 반면, SwiftUI 의 `onMoveCommand` 는 **"위로 이동하려는 의도"** 라는 한 단계 추상화된 신호를 준다 (예: 접근성 보조기기로도 같은 의도가 들어옴).
>
> 참고: 더 저수준으로 특정 키를 직접 잡고 싶으면 `.onKeyPress(.upArrow) { ... }` (macOS 14+) 도 있다. 이번엔 의미가 명확한 `.onMoveCommand` 로 간다.

### 3) `@FocusState` 의 이 단계 새 측면 — 클릭으로 포커스 주입

08 에서는 `@FocusState` 를 **"다이얼로그 뜨면 onAppear 에서 자동 포커스"** 한 방향(코드→포커스)으로만 썼다. 이번엔 반대로 **사용자 클릭 → 포커스** 도 필요하다. `.focusable()` 만으로는 `Tab` 키로는 포커스가 가도 **마우스 클릭으로는 잘 안 가는** 경우가 많다 → `@FocusState` 를 직접 true 로 밀어줘야 자연스럽다 (구현 가이드 힌트 참고).

### 상태 모델
오전/오후는 Bool 보다 **의미가 드러나는 enum** 이 낫다 (09·10 의 mode enum 과 같은 결):

```swift
enum Meridiem {
    case am, pm

    var label: String {
        // TODO: .am → "오전", .pm → "오후"
    }

    mutating func toggle() {
        // TODO: am ↔ pm
    }
}
```

> Java 비유: `enum Meridiem { AM, PM }` 에 메서드 단 것과 동일. Swift enum 은 `mutating func` 로 자기 자신 케이스를 바꿀 수 있다 (값 타입이라 `mutating` 표시 필요 — Java enum 과 다른 점).

### 뷰 골격

```swift
struct BorderlessTimePicker: View {
    @State private var meridiem: Meridiem = .am
    @FocusState private var isFocused: Bool

    var body: some View {
        Text(meridiem.label)
            // TODO: .focusable()
            // TODO: .focused($isFocused)
            // TODO: .onTapGesture { ... }          // 클릭 → 포커스
            // TODO: .onMoveCommand { direction in ... }  // ↑/↓ → meridiem.toggle()
            // TODO: 포커스 상태 시각 표시 (아래 힌트)
            .padding(.horizontal, 6)
            .padding(.vertical, 2)
    }
}

}
```

### 막힐 만한 지점 — 힌트

- **클릭해도 포커스가 안 간다** — `.focusable()` 만으로는 `Tab` 으로만 포커스가 가는 경우가 흔하다. `.onTapGesture { isFocused = true }` 로 클릭 시 `@FocusState` 를 직접 true 로 밀어준다. (`@FocusState` 는 08 에서 배운 그대로, 방향만 코드→시스템.)
- **화살표를 눌러도 토글이 안 된다** — `onMoveCommand` 는 **포커스된 동안만** 불린다. 먼저 클릭(또는 Tab)으로 포커스가 실제로 갔는지부터 확인. 포커스 표시(아래)를 해두면 디버깅이 쉬워진다.
- **포커스됐는지 눈에 안 보인다** — 커스텀 뷰는 포커스 링이 자동으로 안 예쁘게 붙는다. `isFocused` 값으로 직접 표시하자. 예: `.background` 에 `RoundedRectangle` 을 깔고 `isFocused ? Color.accentColor.opacity(0.2) : .clear`, 또는 `.overlay` 로 테두리. (정답 아님 — 취향껏.)
- **`.onMoveCommand` 의 클로저 파라미터 타입이 헷갈림** — `MoveCommandDirection`. `.up / .down / .left / .right`. 이번엔 `.up`, `.down` 둘 다 토글로 처리하면 충분(좌우는 `default` 로 무시).
- **enum `toggle()` 에서 컴파일 에러** — `mutating` 키워드 빠졌을 가능성. enum 은 값 타입이라 자기 케이스를 바꾸는 메서드엔 `mutating` 필요.
