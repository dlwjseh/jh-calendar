# 단계 5: 시(hour) 숫자 입력 (.onKeyPress · 클램프 버퍼)

> 04 의 오전/오후 토글 옆에 **"시" 입력 칸** 을 붙인다. 클릭→포커스는 04 와 동일.
> 새로 배우는 핵심은 **`.onKeyPress` 로 숫자 키를 받아** 12시제 규칙대로 누적하는 것.

## 학습 목표
이 단계를 마치면:
- 포커스된 뷰에서 **숫자 키 입력을 `.onKeyPress` 로 가로채** 상태에 반영할 수 있다.
- "두 자리까지 누적하되 **12 초과면 마지막 숫자만**, 0 이면 오전/오후 뒤집고 12" 같은 **입력 버퍼 규칙** 을 직접 설계·구현할 수 있다.
- `String(format:)` 로 두 자리 zero-pad 표시를 만들 수 있다.
- 결과물: `BorderlessTimePicker` 가 `[시] [오전/오후]` 두 칸. 시 칸 클릭→포커스 후 숫자를 치면 1~12 범위로 들어가고, "13" 치면 "3" 만 남고, 0 으로 떨어지면 오전↔오후가 뒤집히며 12 가 된다.

## Swift / SwiftUI 개념 (이 단계에서 **새로** 배우는 것만)

### `.onKeyPress` — 키 입력을 직접 받기

04 의 `.onMoveCommand` 는 화살표("이동 의도")만 받았다. 일반 **문자/숫자 키** 를 받으려면 `.onKeyPress` 를 쓴다. 포커스된 뷰에만 온다(04 와 동일 전제).

```swift
.onKeyPress { keyPress in
    // keyPress.characters : 눌린 문자 (String, 보통 한 글자)
    // keyPress.key        : 특수키 표현 (.return, .tab, .escape ...)
    if let digit = Int(keyPress.characters), (0...9).contains(digit) {
        // TODO: digit 으로 hour 갱신
        return .handled      // "내가 처리했음 — 더 전파 마"
    }
    return .ignored          // "관심 없음 — 시스템/다음 핸들러로"
}
```

핵심은 **반환값 `KeyPress.Result`**:

| 반환 | 의미 |
|---|---|
| `.handled` | 이 키를 내가 소비함. 시스템 기본 동작/상위로 전파 안 됨 |
| `.ignored` | 처리 안 함. 평소대로 흘려보냄 (예: Tab 으로 포커스 이동은 그대로 동작) |

> **JS 비유** (Vue/JS 경험 기준): DOM `keydown` 핸들러와 같은 자리. `keyPress.characters` ≈ `event.key`. `return .handled` ≈ `event.preventDefault()` + `stopPropagation()` (기본 동작 막고 소비), `return .ignored` ≈ 핸들러에서 아무것도 안 하고 통과시키는 것.
> **Java 비유**: Swing `KeyListener.keyTyped(KeyEvent)` 와 결이 같다. 다만 SwiftUI 는 "소비했는지" 를 리스너 등록이 아니라 **반환값** 으로 표현.

특정 문자만 받고 싶으면 필터형도 있다 (참고만 — 이번엔 위의 일반형으로 충분):
```swift
.onKeyPress(characters: .decimalDigits) { keyPress in ... }
```

> 04 의 `.onKeyPress(.upArrow)` 한 줄 언급은 "그런 게 있다" 수준이었고, **이번이 실제로 `.onKeyPress` 를 쓰는 첫 단계** 다.

## 구현 가이드
> 정답 풀코드는 제공하지 않는다. 골격 + 규칙 + 힌트만. 와이어링은 직접.

### 파일 변경 계획
- `BorderlessTimePicker.swift` 한 파일만 수정. 새 파일 없음.
- 이제 **포커스 받는 칸이 2개**(시, 오전/오후) → `@FocusState` 가 둘 필요.
  - 04 의 `isFocused` 를 의미가 드러나게 `isMeridiemFocused` 로 **이름만 바꾸고**, 시 칸용 `isHourFocused` 를 새로 추가.
  - (여러 칸 포커스를 enum 하나로 관리하는 더 관용적인 방법이 있는데, 그건 ←/→ 칸 이동 단계에서 — 지금은 Bool 두 개로 충분. 아래 "조금 더" 참고.)
- 레이아웃: `HStack` 으로 `[시 Text] [오전/오후 Text]` 나란히.

### 상태
```swift
@State private var hour: Int = 12          // 12시제 1~12
@State private var meridiem: Meridiem = .am
@FocusState private var isHourFocused: Bool
@FocusState private var isMeridiemFocused: Bool
```

### 시 칸 골격
```swift

    .padding(.vertical, 2)
    .focusable()
    .focused($isHourFocused)
    .onTapGesture { isHourFocused = true }
    .onKeyPress { keyPress in
        // TODO: keyPress.characters → 0~9 정수 digit 추출
        // TODO: 아래 "입력 규칙" 적용 후 .handled
        // 숫자 아니면 .ignored
    }
```

### 입력 규칙 (이 단계의 핵심 로직 — 정확히 이대로)
숫자 `d`(0~9) 가 들어오면:

1. `candidate = hour * 10 + d`
2. `newHour = candidate <= 12 ? candidate : d`  ← **12 초과면 방금 친 숫자만 남김**
3. `if newHour == 0 { meridiem.toggle(); newHour = 12 }`  ← **0 이면 오전/오후 뒤집고 12**
4. `hour = newHour`

검산 (직접 손으로 따라가 볼 것):
- 시작 `hour=12`. `1` → candidate 121 > 12 → `1`. 이어서 `3` → candidate 13 > 12 → `3`. ("13 치면 3만" ✔)
- `1` 친 뒤 `2` → candidate 12 ≤ 12 → `12`. (12 유효 ✔)
- `hour=5` 에서 `0` → candidate 50 > 12 → 0 → 규칙3 발동: meridiem 토글 + `12`. ✔
- `hour=1` 에서 `0` → candidate 10 ≤ 12 → `10`. (이 경우 0 은 자연스럽게 10 의 일부)

### 표시 — 두 자리 zero-pad
```swift
String(format: "%02d", hour)   // 9 → "09", 12 → "12"
```
> Java 의 `String.format("%02d", h)` 와 동일한 포맷 지정자. Swift 는 `Foundation` 의 `String(format:)`.

### 막힐 만한 지점 — 힌트
- **`keyPress.characters` 가 빈 문자열/특수키일 때** — `Int("")` 는 `nil`. `if let digit = Int(keyPress.characters), (0...9).contains(digit)` 로 한 번에 거른다. 통과 못 하면 `return .ignored`.
- **Tab 으로 칸 이동이 안 된다** — 숫자 외 키에서 `.handled` 를 반환하면 Tab 까지 먹어버린다. **숫자일 때만 `.handled`, 그 외 전부 `.ignored`**.
- **`.onMoveCommand` 는 시 칸에 안 붙여도 된다** — 이 단계 범위는 숫자 입력만. 04 의 오전/오후 칸 `.onMoveCommand` 는 그대로 둔다.
- **`isFocused` 이름 바꿨더니 04 코드가 깨짐** — `.focused($isFocused)`, `.onTapGesture { isFocused = true }`, `.onMoveCommand` 주변까지 `isMeridiemFocused` 로 일괄 변경했는지 확인.
- **규칙 3 의 `meridiem.toggle()` 호출 위치** — `hour` 확정 전에 0 판정. enum `toggle()` 은 04 에서 만든 그거 재사용.

- **분(minute) 입력**: 같은 `.onKeyPress` 패턴. 단 상한이 59, "60 초과 시 마지막 숫자" + 두 자리 누적 규칙은 시와 미묘하게 다름(0~59, 0 허용).
