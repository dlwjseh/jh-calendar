# 단계 1: 시작일 → 종료일 자동 보정

> 새 개념 없음. `.onChange(of:)` 을 `AddEventDialog` 안에서 한 번 더 쓰는 작업.
> `.onChange(of:)` → [01-04 페이드 인 아웃](../01-타이틀바-호버표시/04-페이드%20인%20아웃%20애니메이션.md) 참고.

## 작업 목표
다이얼로그에서 **시작일(startDate)을 수정해 종료일(endDate)보다 뒤로 가면** 종료일을 자동으로 따라오게 한다.

- 종료일 = 시작일 + 1시간 (`isAllDay` 와 무관 — 종일 모드는 저장 시 `startOfDay` 로 어차피 정규화됨)
- **제약**: 자동 보정 결과로 **종료일의 "일(day)" 이 시작일의 "일" 과 달라지지 않게** 캡. 즉 시작이 23:30 인 케이스에서 +1h = 익일 00:30 으로 넘어가면 안 되고, 시작과 같은 날 끝(23:59)으로 자른다.

> 반대 방향(end 를 start 앞으로 당기는 경우)은 **이번 단계 범위 외** — 사용자 의도가 더 모호해서 일부러 안 건드린다.

## 사전 산출물
- `AddEventDialog.swift` — `@State startDate`, `@State endDate`, `PopoverDatePicker(date: $startDate)`

## 작업 가이드

**1) `.onChange(of: startDate)` 를 다이얼로그 본문에 부착**

`body` 의 최상위 `VStack` 끝 어딘가(이미 다른 modifier 들이 줄지어 붙어있는 위치)에 한 줄 추가:

```swift
.onChange(of: startDate) { _, newStart in
    if newStart > endDate {
        // TODO: endDate 보정 (+1h, 같은 날 캡)
    }
}
```

- 두 인자 시그니처(`_, newStart`) 는 01-04 와 동일.
- `newStart > endDate` 비교는 `Date` 끼리 직접 가능 (`Comparable`).

**2) +1시간 + "같은 날" 캡**

```swift
let cal = Calendar.current
let oneHourLater = cal.date(byAdding: .hour, value: 1, to: newStart) ?? newStart
let sameDayEnd   = cal.date(bySettingHour: 23, minute: 59, second: 0, of: newStart) ?? newStart
endDate = min(oneHourLater, sameDayEnd)
```

- `Calendar.date(byAdding:value:to:)` 는 옵셔널을 돌려준다(이론상 실패 가능) → `??` 폴백.
- `Calendar.date(bySettingHour:minute:second:of:)` 는 **연/월/일은 유지하면서 시·분·초만 갈아끼우는** 헬퍼. `BorderlessTimePicker.commit(...)` 이 `DateComponents` 로 풀어 다시 합성하는 것과 같은 의도의 **숏컷**.
- `min(...)` 으로 두 후보 중 빠른 쪽을 선택 — 평상시엔 `oneHourLater`, 23시 이후엔 `sameDayEnd` 가 이긴다.

> 종일 모드(`isAllDay == true`)에서도 분기 없이 같은 코드가 돈다. 결과적으로 endDate 의 **일(day)** 은 항상 startDate 의 일과 같아지고, 저장 시 `Calendar.current.startOfDay(for:)` 가 시·분을 평탄화한다 — 사용자 입장에선 "종료일이 시작일과 같은 날로 따라옴" 으로 보인다.

**3) (참고) `startDate` 가 트리거되는 모든 경로**
`PopoverDatePicker` 는 날짜를, `BorderlessTimePicker` 는 시·분을 같은 `$startDate` 에 쓴다. 둘 다 변경 시 `.onChange` 가 발화한다. 시간 1분 앞당겼는데 종료가 자동으로 따라오는 동작은 자연스러우니 조건을 더 좁힐 필요 없음.

## 직접 구현하기
- [ ] `body` 어딘가에 `.onChange(of: startDate) { _, newStart in ... }` 추가
- [ ] `newStart > endDate` 조건 안에서 `+1h` 와 `같은 날 끝` 의 `min` 으로 `endDate` 갱신
- [ ] 시작 14:00 → 시작 16:00 로 옮기고 종료가 그보다 앞이었으면 → 종료 17:00 으로 자동 보정되는지
- [ ] **경계 케이스**: 시작 23:30 으로 이동 → 종료가 23:59 로 캡되고 다음날로 넘어가지 **않는지**
- [ ] 종일 ON 인 채로 시작일을 며칠 뒤로 옮기면 → 종료일이 같은 날로 따라오는지 (저장하면 startOfDay 로 정규화)

## 자가 점검
- 빌드 통과?
- 종료일이 자동 보정될 때 `isSaveEnabled`(`endDate >= startDate`) 가 깨지지 않는지?
- 시작일을 종료일보다 **앞당기는** 변경은 종료일을 건드리지 **않는지**?
- 퀴즈: `Calendar.date(byAdding:value:to:)` 와 `Calendar.date(bySettingHour:minute:second:of:)` 의 차이 — 전자는 "더한다", 후자는 "교체한다". 우리 코드에서 각각 어떤 역할?
