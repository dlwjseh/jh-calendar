# 단계 1: 시작일 → 종료일 자동 보정

> 새 개념 없음. `.onChange(of:)` 을 `AddEventDialog` 안에서 한 번 더 쓰는 작업.
> `.onChange(of:)` → [01-04 페이드 인 아웃](../01-타이틀바-호버표시/04-페이드%20인%20아웃%20애니메이션.md) 참고.

## 작업 목표
다이얼로그에서 **시작일(startDate)을 수정해 종료일(endDate)보다 뒤로 가면** 종료일을 자동으로 따라오게 한다.

- 종일(`isAllDay == true`) → 종료일 = 시작일 (같은 날)
- 시간지정(`isAllDay == false`) → 종료일 = 시작일 + 1시간

> 반대 방향(end 를 start 앞으로 당기는 경우)은 **이번 단계 범위 외**. 사용자 의도가 더 모호하기 때문에 일부러 손대지 않는다.

## 사전 산출물
- `AddEventDialog.swift` — `@State startDate`, `@State endDate`, `@State isAllDay`, `PopoverDatePicker(date: $startDate)`

## 작업 가이드

**1) `.onChange(of: startDate)` 를 다이얼로그 본문에 부착**

`body` 의 최상위 `VStack` 끝 어딘가(이미 다른 modifier 들이 줄지어 붙어있는 위치)에 한 줄 추가:

```swift
.onChange(of: startDate) { _, newStart in
    if newStart > endDate {
        // TODO: isAllDay 에 따라 endDate 보정
    }
}
```

- 두 인자 시그니처(`_, newStart`) 는 01-04 와 동일.
- `newStart > endDate` 비교는 `Date` 끼리 직접 가능 (`Comparable`).

**2) `isAllDay` 분기**

```swift
if isAllDay {
    endDate = newStart                                    // 그대로 맞춤
} else {
    endDate = Calendar.current.date(                      // 1시간 뒤
        byAdding: .hour, value: 1, to: newStart
    ) ?? newStart
}
```

- `Calendar.date(byAdding:value:to:)` 는 옵셔널을 돌려준다 (이론상 실패 가능). `??` 로 폴백.
- 종일 모드일 때 `endDate` 가 `newStart` 와 똑같은 시각이어도 OK — 저장 시점에 어차피 `startOfDay` 로 정규화되는 로직이 이미 있음.

**3) (선택) 시작 시간 자체가 바뀐 경우**
`PopoverDatePicker` 는 날짜만 다루지만 `BorderlessTimePicker` 도 같은 `startDate` 를 바인딩한다. 시간만 1분 앞으로 가도 `startDate` 값이 바뀌어 `.onChange` 가 트리거된다 — 이 동작이 거슬리면 `if isAllDay || newStart > endDate` 같이 조건을 한 줄 더 좁힐 수도 있지만, 굳이 안 좁혀도 자연스럽다(시간 1분 앞당겼는데 종료가 자동으로 따라오는 건 흔한 동작).

## 직접 구현하기
- [ ] `body` 어딘가에 `.onChange(of: startDate) { _, newStart in ... }` 추가
- [ ] `newStart > endDate` 조건 안에서 `isAllDay` 로 분기해 `endDate` 갱신
- [ ] 종일 ON: 시작일을 종료일 뒤로 옮기면 종료일이 같은 날로 따라오는지 확인
- [ ] 종일 OFF: 시작 14:00 → 시작 16:00 로 옮기고 종료가 그보다 앞이었으면 → 종료 17:00 으로 자동 보정되는지 확인
