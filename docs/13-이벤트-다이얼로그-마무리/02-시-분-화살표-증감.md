# 단계 2: 시·분 칸에서 ↑/↓ 화살표로 1씩 증감

> 새 개념 없음. 10-04 에서 오전/오후 칸에 붙였던 `.onMoveCommand` 패턴을 **시·분 칸**으로 확장.
> `.onMoveCommand` → [10-04 시간입력 오전오후 토글](../10-이벤트-추가-다이얼로그/04-시간입력%20오전오후%20토글.md) 참고.

## 작업 목표
`BorderlessTimePicker` 의 **시 칸 / 분 칸**이 포커스된 상태에서 ↑/↓ 화살표를 누르면 각각 1씩 증감한다.

- 시: ↑ = +1시간, ↓ = -1시간 (12 ↔ 1 의 회전과 오전/오후 토글은 `Date` 산술이 알아서 처리)
- 분: ↑ = +1분, ↓ = -1분 (59 → 00 으로 넘어갈 때 시가 자연스럽게 따라 +1)

## 사전 산출물
- `BorderlessTimePicker.swift` — 시·분 `Text` 가 이미 `.focusable()` + `@FocusState` + `.onKeyPress(숫자입력)` 으로 만들어져 있음. 오전/오후 칸엔 `.onMoveCommand` 가 이미 붙어있음.

## 작업 가이드

**1) `Calendar.current.date(byAdding:value:to:)` 한 줄로 충분**

기존 `commit(hour12:minute:meridiem:)` 헬퍼는 키 입력으로 만들어진 **새 hour12 후보** 를 받기 위한 통로다. 화살표는 그냥 현재 `date` 를 ±1 시간/분 한 새 `Date` 를 다시 바인딩하면 끝.

```swift
private func bump(_ component: Calendar.Component, by value: Int) {
    if let next = cal.date(byAdding: component, value: value, to: date) {
        date = next
    }
}
```

- 시간: `bump(.hour, by: +1)` / `bump(.hour, by: -1)`
- 분:   `bump(.minute, by: +1)` / `bump(.minute, by: -1)`
- `Calendar` 가 알아서 회전·캐리(분 59→00 시 +1, 시 11pm→12am 시 날짜 +1) 를 처리한다.

> "다른 칸은 안 건드리고 시만 1씩" 하고 싶다면 더 복잡해진다(분/초 보존). `Date` 산술은 보존이 자동.

**2) 시 칸에 `.onMoveCommand` 추가**

```swift
Text(displayHourFormat)
    .padding(.horizontal, 1)
    .padding(.vertical, 2)
    .focusable()
    .focused($isHourFocused)
    .onTapGesture { isHourFocused = true }
    .onKeyPress { /* 기존 숫자입력 그대로 */ }
    .onMoveCommand { direction in
        switch direction {
        case .up:   bump(.hour, by:  1)   // TODO
        case .down: bump(.hour, by: -1)   // TODO
        default: break
        }
    }
```

- 모디파이어 체인 순서는 자유롭지만 **`.focused`/`.onTapGesture` 와 `.onMoveCommand` 가 같은 `Text` 에 붙어있는 것**이 핵심.
- `.onKeyPress` 와 `.onMoveCommand` 는 서로 다른 이벤트(문자/숫자 vs. 방향키)를 처리하므로 공존 OK.

**3) 분 칸도 같은 패턴**

`.onKeyPress` 옆에 `.onMoveCommand { ... bump(.minute, by: ±1) ... }` 추가.

## 직접 구현하기
- [x] `bump(_:by:)` private 헬퍼 추가
- [x] 시 칸 `Text` 에 `.onMoveCommand` 추가 (↑/↓ 만 처리, 나머지는 `default: break`)
- [x] 분 칸 `Text` 에 `.onMoveCommand` 추가
- [x] 시 칸 포커스 → ↑↓ 로 시간 1씩 움직이는지, 12 ↔ 1 경계에서 오전/오후가 자동으로 바뀌는지 확인
- [x] 분 칸 포커스 → 59 에서 ↑ 누르면 분이 00 이 되면서 시가 +1 되는지 확인

## 자가 점검
- 빌드 통과?
- 시 칸에서 ↑/↓ 가 동작하면서, 기존 숫자 입력(`onKeyPress`)도 여전히 잘 받는지?
- 화살표가 다른 칸(시→분 같은) 포커스 이동에 쓰이지 **않는지** — 우리가 가로채니까 안 넘어가는 게 정상.
- 퀴즈: `commit(hour12:minute:meridiem:)` 을 안 쓰고 `Calendar.date(byAdding:)` 으로 끝내는 게 더 단순한 이유는?

## Claude 리뷰 체크리스트
- [x] `bump` 헬퍼 1곳, 호출부 4곳(시 ↑/↓, 분 ↑/↓) — 중복 로직 없음
- [x] `.onKeyPress` 와 `.onMoveCommand` 공존, 각자 역할 분리
- [x] 회전/캐리를 직접 계산하지 않고 `Calendar` 가 처리하게 둠 (idiomatic)
- [x] 오전/오후 칸의 기존 `.onMoveCommand` 토글은 그대로 (건드리지 않음)
