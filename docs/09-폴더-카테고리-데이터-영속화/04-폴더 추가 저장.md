# 단계 4: 폴더 추가 저장

## 학습 목표
- 뷰에서 `ModelContext` 를 꺼내 `modelContext.insert(...)` 로 실제 데이터를 저장하는 흐름을 익힌다.
- `print()` 자리에 실제 영속화 호출이 들어가는 "샘플 → 실제" 의 첫 전환을 직접 한다.

## 사전 지식
- 1~3단계 산출물 (Folder/Category 모두 `@Model`, Color 영속화 완료)
- `@Environment` 의 개념 (없으면 잠깐 검색해보면 좋음 — Vue 의 `inject` 와 비슷)

## Swift / SwiftUI 개념

### 1) `@Environment(\.modelContext)` — JPA 의 `EntityManager`

```swift
struct AddFolderDialog: View {
    @Environment(\.modelContext) private var modelContext
    @Environment(\.dismiss) private var dismiss
    ...
}
```

`modelContext` 는 **저장/삭제 작업을 수행하는 게이트웨이**. Spring 의 `@PersistenceContext EntityManager em` 과 같은 위치. 우리가 1단계에서 `.modelContainer(for:)` 를 부착해뒀기 때문에 자식 뷰 어디서든 `@Environment` 로 꺼낼 수 있다.

### 2) `modelContext.insert(_:)` & 자동 저장

```swift
let folder = Folder(name: trimmedName)
modelContext.insert(folder)
```

이게 끝이다. **명시적 `save()` 호출이 보통은 필요 없다** — SwiftData 는 컨텍스트가 변경되면 적당한 타이밍(앱 백그라운드 진입, 일정 시간 경과 등)에 자동으로 디스크에 기록한다.

> JPA dirty checking 과 같은 결. 명시적 flush 가 필요한 케이스(테스트 시점 검증, 즉시 동기화)에는 `try? modelContext.save()` 를 호출하면 된다.

### 3) 트림(trim) 처리 — 이미 익숙한 부분

다이얼로그의 `name` 은 `trimmingCharacters(in: .whitespaces)` 한 결과로 저장하는 것이 자연스럽다 (08 단계에서 검증 로직으로 이미 등장).

## 구현 가이드

### 파일 변경 계획
- `AddFolderDialog.swift` — 저장 버튼의 `print(...)` 를 `modelContext.insert(Folder(name: trimmedName))` 로 교체
- (참고) Sidebar 의 `+ → 새 폴더` 흐름이 ContentView 의 `isAddFolderPresented` 토글에 묶여 있으니, 다이얼로그가 닫히기만 해도 `@Query` 가 알아서 새 데이터를 받아 사이드바가 갱신된다.

### 핵심 골격

```swift
// AddFolderDialog.swift
struct AddFolderDialog: View {
    @Binding var isPresented: Bool
    @Environment(\.modelContext) private var modelContext
    @State private var name = ""
    ...

    private func save() {
        let trimmed = name.trimmingCharacters(in: .whitespaces)
        guard !trimmed.isEmpty else { return }
        let folder = Folder(name: trimmed)
        modelContext.insert(folder)
        // TODO: 닫기 애니메이션
    }
}
```

### 막힐 만한 지점 — 힌트

- **저장은 됐는데 사이드바에 안 나타난다** — `@Query` 의 정렬이나 필터가 너무 좁지 않은지, 또 ContentView 가 매 호출마다 `folders` 를 정상적으로 받고 있는지 확인.
- **`modelContext.insert(folder)` 직후 `folder.id` 가 nil 처럼 보임** — SwiftData 의 `PersistentIdentifier` 는 insert 직후엔 임시 식별자였다가 first save 후 영구 식별자로 바뀐다. 보통 우리는 id 자체를 직접 다루지 않으므로 신경 쓸 일 없음.
- **저장 후 다이얼로그 안 닫힘** — `withAnimation { isPresented = false }` 호출이 누락되지 않았는지.
- **사이드바가 처음 실행에서 비어 있다** — 정상. 시드를 두지 않기로 했으니, `+` 버튼으로 직접 폴더를 추가해서 동작을 검증하면 된다.

## 자가 점검
- 사이드바 `+` → 폴더 추가 → 입력 → 저장 시 즉시 사이드바에 새 폴더가 보이는가?
- 앱 재실행 후에도 보이는가?
- 이해도 퀴즈

  2. 만약 즉시 디스크에 쓰고 싶다면 어떤 메서드를 호출해야 하는가? 언제 그게 필요할까?

## 조금 더 (선택)
- 즉시 동기화가 필요할 때 `try? modelContext.save()` 사용 시점을 찾아보기 (테스트, 마이그레이션 직후 등).
- `ModelContext.transaction { ... }` — 여러 insert/delete 를 묶고 싶을 때.
- 첫 실행 시 기본 폴더를 미리 채워두는 "시드" 가 필요해진다면, `@Query` 결과가 비어 있을 때만 insert 하는 idempotent 패턴이나 `@AppStorage` 플래그 방식을 찾아볼 것.
