# 단계 7: 편집 (폴더 이름 / 카테고리 이름·색상)

## 작업 목표
context menu 의 "이름 변경" → 기존 추가 다이얼로그를 **추가/편집 두 모드** 로 재사용. 폴더는 이름만, 카테고리는 이름 + 색상을 변경할 수 있게 한다.

> 새 Swift 개념은 거의 없다. 핵심은 **다이얼로그를 어떤 mode 로 띄우는지** 를 한 군데의 enum/optional 로 표현하고, 저장 로직이 mode 에 따라 분기하는 패턴.

## 사전 지식
- 4~5단계 (추가 저장) 와 6단계 (context menu) 가 끝나 있어야 함
- `@Bindable` 로 class 모델에 binding 만들기 → [02-Category @Model + Relationship.md](./02-Category%20@Model%20%2B%20Relationship.md) 참고

## 작업 가이드

### 다이얼로그 mode 표현 — 두 가지 선택지

**A. enum 으로 명시적 mode**
```swift
enum FolderDialogMode {
    case add
    case edit(Folder)
}

struct AddFolderDialog: View {
    let mode: FolderDialogMode
    ...
}
```

**B. optional 타깃**
```swift
struct AddFolderDialog: View {
    let editing: Folder?   // nil 이면 추가, 있으면 편집
    ...
}
```

> 둘 다 흔한 패턴. A 가 의도가 명시적이고 case 추가 (예: duplicate) 에 강하다. B 가 코드가 짧다. 한쪽으로 일관되게.

### ContentView 의 상태 정리

지금까지 `@State isAddFolderPresented: Bool` 하나로 다이얼로그 가시성을 제어했는데, 편집까지 들어오면 **무엇을 편집 중인지** 까지 들고 있어야 한다. 한 번에 정리:

```swift
@State private var folderDialog: FolderDialogMode? = nil
@State private var categoryDialog: CategoryDialogMode? = nil

// 표시 조건: folderDialog != nil
// 새 폴더: folderDialog = .add
// 폴더 편집: folderDialog = .edit(folder)
```

`isAddFolderPresented` / `isAddCategoryPresented` 를 위 패턴으로 일괄 치환하면 추가/편집 분기가 자연스럽게 흡수된다.

### 저장 로직 분기

```swift
private func save() {
    let trimmed = name.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty else { return }
    switch mode {
    case .add:
        modelContext.insert(Folder(name: trimmed))
    case .edit(let folder):
        folder.name = trimmed   // class 라 그대로 변경 → 자동 dirty tracking
    }
}
```

> JPA dirty checking 과 동일한 결: 영속 객체의 필드를 그냥 수정하면 트랜잭션 종료 시점에 update SQL 이 나간다. SwiftData 도 `modelContext` 가 들고 있는 인스턴스의 변경을 자동 추적해서 다음 자동 save 때 디스크에 반영한다.

### 파일 변경 계획
- `AddFolderDialog.swift` — `mode: FolderDialogMode` (또는 `editing: Folder?`) 받기, 헤더 텍스트 분기 ("폴더 추가" vs "폴더 이름 변경"), `onAppear` 에서 편집 모드면 기존 이름 prefill
- `AddCategoryDialog.swift` — 같은 패턴. 편집 모드에선 폴더 선택 메뉴를 **읽기 전용 or 숨김** 으로 하는 것이 자연스러움 (캘린더 앱들은 보통 카테고리의 소속 폴더 이동을 별도 작업으로 둠). 정책은 본인 의도대로.
- `Sidebar.swift` / `CategoryRow.swift` — context menu 의 "이름 변경" 액션에서 `folderDialog = .edit(folder)` 또는 `categoryDialog = .edit(category)`
- `ContentView.swift` — 상태 표현 일괄 치환 + 다이얼로그 표시 분기

### 막힐 만한 지점 — 힌트

- **편집 모드에서 빈 이름으로 저장하려 할 때** — 추가와 동일하게 trim + 빈 가드. 다만 편집은 "원래 이름이 비어 있던 적이 없을 것" 이라 분기 이중화하지 말고 `save()` 한 곳에서 가드.
- **`@State private var name = ""` 가 mode 가 바뀌어도 그대로 빈 채** — `.onAppear` 또는 `init` 에서 mode 에 따라 초기값 채우기. SwiftUI 의 `@State` 초기값은 뷰 생성 시 한 번만 평가됨에 주의.
- **편집 도중 사용자가 다이얼로그 밖을 클릭해서 닫힐 때** — 저장 안 한 변경은 버려져야 한다 (현재 다이얼로그가 model 직접 수정이 아니라 `name` State 를 들고 있다가 save 시점에 옮기는 구조라면 자연스럽게 처리됨). 만약 `@Bindable` 로 모델 직접 편집을 택했다면 취소 시 원복 로직이 필요해진다 — 추천하지 않음.
- **카테고리 색상 편집** — `@State selectedColor` 를 편집 모드에서 `category.color` 로 초기화, 저장 시 `category.color = selectedColor` 한 줄로 끝. 폴더는 Folder 인스턴스를 통해 접근.

## 자가 점검
- 폴더 이름 변경 → 사이드바 즉시 반영?
- 카테고리 이름/색상 변경 → 사이드바 점색 + 라벨 즉시 반영?
- 편집 모드에서 폴더 선택을 숨김/잠금했다면 의도된 정책인지 확인
- 이해도 퀴즈
  1. `folder.name = newValue` 한 줄만 했는데 디스크까지 갱신되는 이유는?
  2. 편집 다이얼로그를 닫았을 때 저장 안 된 변경이 버려지는 게, 우리가 택한 구조 (State + save 시점 옮기기) 에서 어떻게 자연스럽게 처리되는가?
