# 단계 3: 삭제 애니메이션

> 새 개념 없음. `withAnimation` + `.transition` 의 협력 패턴은 [03-03](../03-사이드바-슬라이드/03-slide%20애니메이션과%20transition.md), [01-04](../01-타이틀바-호버표시/04-페이드%20인%20아웃%20애니메이션.md) 에서 다뤘다. ForEach 의 stable identity 는 [07-02](../07-사이드바-토글-다듬기/02-DayCell%20id%20안정화%20-%20자연키%20패턴.md).

## 작업 목표
이벤트 삭제 시 다음 세 곳이 "쓱" 사라지게:
- **일 팝업의 행** (15-1 의 삭제 경로)
- **달력 셀 안의 단일 일 이벤트 마커** (dot + 이름)
- **달력 멀티데이 바**

수정 다이얼로그 삭제 (15-2) 도 같은 흐름에 다이얼로그 닫힘이 자연스럽게 합쳐지도록.

## 사전 산출물
- 15-1 의 `DayPopupEventRow` 의 `modelContext.delete(event)` 호출
- 15-2 의 `AddEventDialog` 의 `modelContext.delete(event) + onDismiss()` 호출
- 단일 일 이벤트 마커: `DayCellView` 의 `ForEach(events) { ... }`
- 멀티데이 바: `WeekRowView` 의 `ForEach(laned, id: \.event.id) { ... }`

## 작업 가이드

### 1) 삭제 호출을 `withAnimation` 으로 감싸기

두 곳 모두 같은 톤. 이미 dialog 닫힘에 쓰던 `.smooth(duration: 0.3)` 와 맞추면 일관:

```swift
// 15-1: DayPopupEventRow 의 contextMenu 안
Button("삭제", role: .destructive) {
    withAnimation(.smooth(duration: 0.25)) {
        modelContext.delete(event)
    }
}

// 15-2: AddEventDialog 의 삭제 버튼
HoverButton {
    withAnimation(.smooth(duration: 0.3)) {
        modelContext.delete(event)
        onDismiss()   // 삭제 + 닫기가 같은 애니메이션 트랜잭션
    }
} label: { ... }
```

`onDismiss()` 가 `withAnimation` 블록 안에 있으므로 dialog 닫힘 (`opacity + scale` transition, ContentView 참고) 도 같은 타이밍에 트리거.

### 2) 사라지는 view 들에 `.transition(_:)` 부착

`withAnimation` 만으론 부족 — view 가 사라지는 동안 "어떻게" 보일지 룰이 필요. 디폴트는 instant (아무 효과 없음).

**`DayPopupEventRow`** — `body` 최상위 `HStack`(modifier chain 끝) 에:

```swift
.transition(.opacity)
```

**`DayCellView` 의 이벤트 행** — `ForEach(events) { ... }` 안 각 행에:

```swift
.transition(.opacity)
```

**`WeekRowView` 의 멀티데이 바** — `ForEach(laned, id: \.event.id) { ... }` 안 바 컨테이너에:

```swift
.transition(.opacity)
```

> 더 강한 효과를 원하면 `.opacity.combined(with: .scale(scale: 0.95))` — 살짝 줄어들면서 페이드. 일단 `.opacity` 만으로 충분한지 보고 부족하면 결합.

### 3) SwiftData `@Query` 보정 — `.animation(_:value:)`

`withAnimation { modelContext.delete(event) }` 만으로는 **거의 동작하지 않을 가능성이 높다.** 이유:

1. `withAnimation` 블록은 **동기적으로** 실행되고 즉시 종료된다.
2. `modelContext.delete(_:)` 는 모델 store 만 변경한다. ForEach 가 보고 있는 `@Query` 결과 (`dayEvents`, `allEvents`) 는 **다음 run loop** 에서 갱신된다.
3. 결과: 데이터 변경 시점에 트랜잭션이 이미 닫혀 있어 `.transition` 이 트리거되지 않고 instant 제거된다.

해결은 **view 측에서 트랜잭션을 보장** — 데이터를 watch 하는 곳에 `.animation(_:value:)` 부착:

```swift
// DayPopupDialog 의 ForEach(dayEvents) 든 컨테이너에
.animation(.smooth(duration: 0.25), value: dayEvents)

// MonthlyCalendarView 의 일 그리드 VStack 에
.animation(.smooth(duration: 0.25), value: allEvents)
```

- `Event` 가 `@Model` → Identifiable + Equatable 이라 `value:` 비교 가능.
- `withAnimation` 도 그대로 둔다 — 다이얼로그 닫힘 (`eventDialog = nil`) 같은 **동기 state 변경** 에는 `withAnimation` 이 동작한다. 둘은 보완 관계.
- 만약 `value: allEvents` 가 변경 감지 못 하면 `value: allEvents.map(\.id)` fallback.

> Vue 비유: `@Query` 결과 갱신이 `nextTick` 안에서 일어나는 셈이라, `<transition-group>` 같은 view 측 watcher 가 있어야 트랜잭션이 잡힌다.

### 4) Stable identity 확인

`.transition` 이 동작하려면 ForEach 가 view identity 를 유지해야 함. 그래야 SwiftUI 가 "이 view 가 사라진다" 를 알고 transition 을 트리거.

- `DayPopupDialog` 의 `ForEach(dayEvents) { ... }` — `Event` 가 `@Model`(Identifiable) → OK
- `WeekRowView` 의 `ForEach(laned, id: \.event.id)` → OK
- `DayCellView` 의 `ForEach(events) { ... }` → 같은 결로 OK

만약 transition 이 안 보이면 stable id 가 깨졌을 가능성 — [07-02](../07-사이드바-토글-다듬기/02-DayCell%20id%20안정화%20-%20자연키%20패턴.md) 에서 다룬 자연키/안정 id 패턴 점검.

## 자가 점검
- 빌드 통과?
- 일 팝업에서 우클릭 삭제 → 행 + 달력 마커가 동시에 페이드아웃?
- 멀티데이 삭제 → 모든 주의 바가 동시에 같은 타이밍으로 페이드아웃?
- 수정 다이얼로그 삭제 → 다이얼로그 닫힘 + 마커 페이드아웃이 한 트랜잭션?
- 비교 실험: 한 쪽 (예: `withAnimation` 만 두고 `.transition` 제거) 만 두면 어떻게 보이는지 (instant 제거 확인 — 두 협력의 필요성 체감)
- 퀴즈: `.transition(.opacity)` 가 **insertion** 에도 영향을 주는가? insertion / removal 분리하려면 어떤 transition 을 써야 하나? (`AsymmetricTransition` / `.transition(.asymmetric(insertion:, removal:))`)
