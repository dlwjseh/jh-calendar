# 단계 3: 팝업 `＋` → 이벤트 추가 (그 날짜 프리필)

## 학습 목표
- 일 팝업의 `＋` 버튼을 누르면 팝업이 닫히고 **이벤트 추가 다이얼로그**가 열린다.
- 추가 다이얼로그의 **시작/종료일이 팝업에서 보던 그 날짜**로 채워져 있다.

## 사전 지식
- 02 완료(`DayPopupDialog`, `ContentView` 의 `dayPopup` 상태)
- `ContentView` 의 `eventDialog: EventDialogMode?` + `AddEventDialog(mode:)` 패턴
- `AddEventDialog` 의 `@State startDate/endDate` 가 현재 `Date()` 로 고정 초기화된다는 점

## Swift / SwiftUI 개념 (이 단계의 핵심)

### 1) enum 연관값으로 데이터 함께 넘기기
`.edit(Event)` 가 이미 이벤트를 싣고 다니듯, `.add` 에도 날짜를 싣는다:

```swift
enum EventDialogMode {
    case add(Date)        // 시작/종료 프리필 기준일
    case edit(Event)
}
```
- 호출부에서 `eventDialog = .add(someDate)`.
- 기존 `.add` 무인자 호출부(FloatingToolbar 등)가 깨지면 `.add(Date())` 로 맞춰주면 된다. (컴파일러가 다 잡아준다 — Swift enum 의 장점. Java enum 엔 없는 연관값 개념.)

### 2) `@State` 를 `init` 에서 초기화 — 밑줄(`_`) 접근
지금 `AddEventDialog` 은 `@State private var startDate = Date()` 라 **항상 오늘**로 시작한다. 외부 값으로 시작하게 하려면 `init` 에서 초기화해야 한다.

`@State var x` 는 사실 `_x` 라는 `State<T>` 저장 프로퍼티의 래퍼다. `init` 안에서는 **밑줄 이름에 `State(initialValue:)`** 를 대입한다:

```swift
@State private var startDate: Date
@State private var endDate: Date

init(mode: EventDialogMode, categories: [Category], onDismiss: @escaping () -> Void) {
    self.mode = mode
    self.categories = categories
    self.onDismiss = onDismiss

    switch mode {
    case .add(let day):
        _startDate = State(initialValue: day)
        _endDate   = State(initialValue: day)
    case .edit(let event):
        _startDate = State(initialValue: event.startDate)
        _endDate   = State(initialValue: event.endDate)
        // name/isAllDay/category 프리필은 04 에서
    }
}
```
- 주의: `_x = State(initialValue:)` 는 **`init` 안에서 단 한 번**만 의미가 있다. 이후 `mode` 가 바뀐다고 자동 갱신되지 않는다 — 여기선 다이얼로그가 매번 새로 생성·파괴되므로(모달 토글) 문제 없음.
- 비교: Vue `data()` 가 `props` 초깃값을 한 번 읽어 reactive state 를 만드는 것과 같은 결. 이후 prop 변경이 자동 반영 안 되는 것도 비슷.
- `let mode`/`categories` 도 `init` 에서 대입하므로 기존 `init` 골격은 유지하고 `_startDate/_endDate` 줄만 추가하면 된다.

## 구현 가이드
> 정답 풀코드는 제공하지 않는다.

**A. `EventDialogMode`** — `.add` 에 `Date` 연관값 추가. 기존 `.add` 사용처 컴파일 에러를 따라가며 `.add(...)` 로 수정(FloatingToolbar 의 "이벤트 추가" 버튼은 오늘 날짜 `.add(Date())` 로).

**B. `AddEventDialog`**
- `@State startDate/endDate` 를 선언만(타입 명시) 하고 기본값 제거.
- `init` 에서 `mode` 분기해 `_startDate/_endDate` 세팅(위 스니펫). `.edit` 의 나머지 필드는 04 에서.

**C. `DayPopupDialog` → 위로 콜백**
- `var onAddEvent: (Date) -> Void` 추가(클로저 주입, `onDismiss` 와 동형).
- 헤더 우상단 `＋` 버튼 `action` 에서 `onAddEvent(date)`.

**D. `ContentView` 배선**
- `DayPopupDialog(date: day, onAddEvent: { d in ... })`:
  - 팝업 닫고 → 추가 다이얼로그 열기. 두 상태가 한 곳이라 간단:

```swift
onAddEvent: { d in
    withAnimation(.smooth(duration: 0.3)) {
        dayPopup = nil
        eventDialog = .add(d)     // TODO
    }
}
```
  - 동시에 둘 다 켜지지 않게 순서/애니메이션 확인(전환이 자연스러운지).

## 직접 구현하기

- [ ] `AddEventDialog`: `@State` 선언부 + `init` 에서 `_startDate/_endDate` 프리필
- [ ] `DayPopupDialog`: `onAddEvent` 콜백 + `＋` 버튼 연결
- [ ] `ContentView`: 팝업→추가 전환 배선

## 자가 점검 (구현 후)
- 빌드 통과? (`.add` 사용처 다 고쳤나)
- 다른 날에서 `＋` 누르면 그 날짜로 채워지나? 종일/시간 토글·저장 정상?
- 팝업이 먼저 닫히고 추가 폼이 뜨나(겹침/깜빡임 없나)?
- 퀴즈: `@State private var x = Date()` 와 `init` 의 `_x = State(initialValue:)` 의 차이는? 왜 후자가 필요한가?
