# 단계 4: 이벤트 클릭 → 수정 다이얼로그 (`.edit` 프리필 완성)

> 새 개념은 거의 없음 — 03 에서 만든 **`init` State 프리필 패턴**을 `.edit` 의 나머지 필드로 확장 + 02 의 콜백 패턴 재사용. **작업 가이드** 위주.
> State init → [03-팝업-추가버튼-날짜프리필.md](03-팝업-추가버튼-날짜프리필.md), 콜백 주입 → [02-일클릭-팝업-모달.md](02-일클릭-팝업-모달.md) 참고.

## 작업 목표
- 일 팝업의 **이벤트 행을 클릭**하면 팝업이 닫히고 그 이벤트의 **수정 다이얼로그**가 열린다.
- 수정 다이얼로그가 **모든 필드(이벤트명·종일·카테고리·시작·종료)로 프리필**된다 → 11-01 의 "후속: `.edit` 프리필" 항목 종료.

## 사전 산출물
- 02(`DayPopupDialog`, 이벤트 행), 03(`AddEventDialog` 의 `init` State 프리필 골격 — `.edit` 의 날짜는 이미 채워짐)

## 작업 가이드

**1) `.edit` 나머지 필드 프리필 (`AddEventDialog.init`)**
03 에서 `.edit(let event)` 의 `_startDate/_endDate` 는 채웠다. 같은 자리에서 나머지도:

```swift
case .edit(let event):
    _startDate = State(initialValue: event.startDate)
    _endDate   = State(initialValue: event.endDate)
    _name      = State(initialValue: event.name)        // TODO
    _isAllDay  = State(initialValue: event.isAllDay)     // TODO
    _selectedCategory = State(initialValue: event.category)  // TODO
```
- `selectedCategory` 는 `Category?` 참조. **`event.category` 그 객체 자체**를 넣어야 칩 선택 비교(`==`/식별)가 맞는다. `categories` 배열에서 다시 찾을 필요 없음(같은 SwiftData 인스턴스).
- `.add(let day)` 쪽은 03 그대로(이름 빈값·종일 기본값 유지).
- 저장 로직(`switch mode { case .edit(let event): event.name = ... }`)은 이미 있으니 건드릴 필요 없음 — 이번엔 **읽어와 채우는** 쪽만.

**2) 이벤트 행 → 위로 콜백 (`DayPopupDialog`)**
- `var onEditEvent: (Event) -> Void` 추가.
- 이벤트 행에 `.contentShape(Rectangle())` + `.onTapGesture { onEditEvent(e) }` (02 의 셀 클릭과 동형). `＋`(03) 와 행 클릭이 서로 안 먹히게 영역 확인.

**3) `ContentView` 배선**
```swift
DayPopupDialog(
    date: day,
    onAddEvent:  { d in withAnimation(.smooth(duration: 0.3)) { dayPopup = nil; eventDialog = .add(d)  } },
    onEditEvent: { e in withAnimation(.smooth(duration: 0.3)) { dayPopup = nil; eventDialog = .edit(e) } }  // TODO
)
```
