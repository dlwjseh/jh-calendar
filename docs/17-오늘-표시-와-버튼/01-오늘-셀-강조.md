# 단계 1: 오늘 셀 강조 (DayCellView)

## 학습 목표
- `DayCellView` 에서 "이 셀이 오늘인가" 를 판별.
- 오늘인 셀의 day number 뒤에 **컬러 원형 배경** 을 깔고 글자색을 흰색으로 덮어 시각적으로 강조.
- 주말 색 / 다른 달 흐림 색 등 기존 규칙과의 **우선순위** 를 정리.

## 사전 산출물
- `DayCellView.swift` — `cell.day` 를 `Text` 로 그리고 `textColor` (주말/다른 달) 분기가 이미 들어가 있는 상태.
- `DayCell` 은 `date: Date` 를 가지고 있음.

## Swift / SwiftUI 개념

### `Circle()` 을 **배경 레이어** 로 깔기

이전에 `Circle()` 은 `WeekRowView` 의 multiday bar 안 작은 dot 으로만 등장했다. 이번엔 day number 의 **배경** 으로 쓴다.

```swift
Text("\(cell.day)")
    .foregroundStyle(.white)
    .frame(width: 22, height: 22)
    .background {
        Circle().fill(.red)
    }
```

- `.background { ... }` 는 view 의 **뒤쪽 레이어** 를 그린다. (`.overlay { ... }` 는 위쪽.)
- `Circle()` 은 부모의 `frame` 을 꽉 채우는 정원(正圓). day number 글자에 직접 frame 을 주거나 외곽 padding 으로 원형 영역을 잡는다.

> Vue/CSS 비유: `<span style="background: red; border-radius: 50%;">` 와 같은 결. SwiftUI 는 shape primitive 를 그대로 layer 로 합성한다.

### 조건부 layer — "오늘일 때만" 배경

오늘이 아닌 셀은 day number 뒤에 아무것도 그리고 싶지 않다. `if` 분기를 `.background` 안에 그대로 쓸 수 있다.

```swift
Text("\(cell.day)")
    .background {
        if isToday {
            Circle().fill(.red)
        }
    }
```

- if 의 빈 분기 = 아무 view 도 안 그림. `.background` 가 "투명한 무언가" 를 받는 격이라 비용 X.
- 요일 색 분기(`switch weekday`) 와는 결이 다르다 — 색은 항상 "어떤 값" 으로 결정되지만, 배경 layer 는 **있을 수도 / 없을 수도** 있다.

### 우선순위 — "오늘" 이 다른 규칙을 어떻게 덮는가

현재 `textColor` 는:
- 다른 달 → `.secondary`
- 일요일 → `.red`
- 토요일 → `.blue`
- 평일 → `.primary`

여기에 "오늘" 이 끼면 의사결정이 필요하다:

| 케이스 | 처리 |
|---|---|
| 오늘 셀의 글자색 | 빨간 원 위에 있으니 **흰색** 이 자연스러움 |
| 오늘이 일요일/토요일 | 원 + 흰 글자로 덮어 OK |
| 다른 달의 셀이 "오늘" | 그리드 첫/마지막 주에 가능. 그래도 강조하는 게 macOS Calendar 의 동작 |

판단 우선순위를 한 줄로:

> **isToday 가 다른 모든 색 규칙을 덮는다.**

구현은 두 가지 결로 가능:

1. **textColor 분기에 isToday 를 최상단으로 추가** — switch 하나가 다 책임짐.
2. **isToday 일 때 `.foregroundStyle(.white)` 를 나중에 한 번 더** — 기존 분기는 그대로 두고 modifier 체인 뒤쪽에서 덮어쓰기.

둘 다 가능. 1이 "한 곳에서 결정" 이라 추론하기 쉽고, 2가 더 적은 코드 변경. 학습 차원에서 1 권장.

## 구현 가이드

### 1) 오늘 판별

`DayCellView` 안에 computed property:

```swift
private var isToday: Bool {
    Calendar.current.isDateInToday(cell.date)
}
```

> `Calendar.isDateInToday(_:)` 는 시/분/초를 모두 무시하고 "같은 날" 을 본다. 직접 `startOfDay` 비교를 짜는 것보다 훨씬 깔끔. ([Calendar-와-Date 3-8](../자주-쓰는-기술들/Calendar-와-Date.md))

### 2) day number 에 원형 배경

현재 day number 부분:
```swift
Text("\(cell.day)")
    .font(.system(size: 12))
    .foregroundStyle(textColor)
    .padding(.bottom, 4)
```

원형 배경이 너무 크지 않게 frame 을 명시하고 `.background` 로 Circle 을 깐다. 골격:

```swift
Text("\(cell.day)")
    .font(.system(size: 12))
    .foregroundStyle(textColor)
    .frame(width: /* 적당 */, height: /* 적당 */)
    .background {
        if isToday {
            Circle().fill(/* 강조색 */)
        }
    }
    .padding(.bottom, 4)
```

- 강조색: macOS Calendar 는 빨강 계열. `.red` 도 OK, `Color.accentColor` 도 OK. 일관성 차원에서 한 가지 골라 둘 것.
- 원 크기: day number 의 글자(12pt)보다 약간 큰 정사각 frame. 22 ~ 24 정도가 어울림. 너무 작으면 글자가 비집고 나오고, 너무 크면 셀이 답답함. 직접 슬라이드 보면서 조정.

### 3) `textColor` 우선순위 갱신

기존:
```swift
private var textColor: Color {
    if !cell.isInCurrentMonth { return .secondary }
    switch cell.weekday {
        case 1:  return .red
        case 7:  return .blue
        default: return .primary
    }
}
```

여기에 `isToday` 분기 최상단 추가:
```swift
private var textColor: Color {
    if isToday { return .white }
    // ... 기존 분기
}
```

> 의미: "오늘이면 다른 모든 규칙을 무시하고 흰 글자". 위에서 정한 우선순위 룰의 직접적 코드 표현.

## 자가 점검
- 빌드 통과?
- 오늘 (현재 시스템 시각 기준) 의 셀에만 컬러 원이 깔리는가?
- prev/next 로 다른 달로 이동하면 강조가 사라지는가? (다른 달 그리드에 오늘이 잠시 보이는 경우 제외)
- 퀴즈: `.background { if isToday { ... } }` 의 `if` 분기가 false 일 때 view tree 비용은 어느 정도? — 빈 view (EmptyView) 가 되니 사실상 무료. SwiftUI 의 ViewBuilder 가 if 의 빈 분기를 EmptyView 로 해석.
- 퀴즈: `.background` 대신 `.overlay` 를 쓰면 무엇이 달라지는가? — Circle 이 글자 **위에** 덮여 글자가 가려진다.

## 조금 더 (선택)
- 강조색을 `Color.accentColor` 로 두면 시스템 액센트 컬러 변경(System Settings) 에 자동 따라간다.
- 다른 달의 오늘은 **약하게** (예: 옅은 원 + secondary 글자) 표현하는 macOS Calendar 의 결을 따라가고 싶으면 `isToday && !cell.isInCurrentMonth` 분기 한 줄 더.
- 클릭 시 hover 배경 (`isHovered`) 과 오늘 배경이 겹치면 의도와 다르게 보일 수 있음 — hover 색을 살짝 옅게, 또는 오늘 셀에서는 hover 색 비활성화하는 등 조율 가능.
