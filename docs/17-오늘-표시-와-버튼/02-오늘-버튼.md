# 단계 2: "오늘" 버튼 (FloatingToolbar + CalendarStore.today)

## 작업 목표
- `FloatingToolbar` 에 "오늘" 텍스트 버튼을 추가.
- `CalendarStore` 에 `today()` 메서드를 추가 — 호출 시 referenceDate 를 오늘로 되돌리고, 16-2 의 슬라이드를 자연스럽게 재사용한다.
- 이미 현재 달이 오늘 달인 경우엔 **no-op** 으로 처리 (불필요한 슬라이드/재계산 X).

> 새로 배울 Swift / SwiftUI 개념은 없다. 16-1 의 "rebuild 단일 진입점" + 16-2 의 "direction → DispatchQueue.main.async → withAnimation { rebuild }" 패턴을 그대로 응용한다. 학습 섹션을 생략한 이유는 [CLAUDE.md 학습 포인트 작성 원칙](../../CLAUDE.md) 의 3번 항목 참고.

## 사전 산출물
- `CalendarStore` 에 `prevMonth()` / `nextMonth()` / `rebuild(for:)` / `direction` 이 [16-2 의 최종 형태](../16-월-이동/02-슬라이드-애니메이션.md) 로 정착.
- `FloatingToolbar` 에 사이드바 토글 + `+` (이벤트 추가) 두 개의 `HoverButton` 이 들어있는 상태.

## 구현 가이드

### 1) `CalendarStore.today()`

prev/next 와 같은 구조 + 두 가지 추가 결정:

1. **이미 같은 달이면 early return.** `Calendar.isDate(_:equalTo:toGranularity: .month)` 로 비교. ([Calendar-와-Date 3-7](../자주-쓰는-기술들/Calendar-와-Date.md))
2. **direction 결정.** 현재 referenceDate 가 오늘보다 미래면 backward (왼쪽에서 들어옴), 과거면 forward (오른쪽에서 들어옴). `Date` 의 `<` 비교 한 줄.

골격:
```swift
func today() {
    let now = Date()
    let cal = Calendar.current

    // 이미 같은 달이면 아무것도 안 함
    if cal.isDate(now, equalTo: referenceDate, toGranularity: .month) {
        return
    }

    // direction: now 가 referenceDate 보다 과거면, 현재 보고있는 달은 미래 → 뒤로 돌아가는 것 → .backward
    direction = (referenceDate > now) ? .backward : .forward

    DispatchQueue.main.async { [weak self] in
        guard let self else { return }
        withAnimation(.smooth(duration: 0.3)) {
            self.rebuild(for: now)
        }
    }
}
```

> 16-2 함정 ①의 교훈: `direction` 세팅과 `rebuild` 호출은 **반드시 다른 render 패스**. 같은 트랜잭션 안에 두면 떠나는 view 의 transition 방향이 stale 캐시로 튄다. `today()` 도 prev/next 와 같은 구조로 가야 함.

### 2) `FloatingToolbar` 슬롯 추가

현재 두 개의 `HoverButton` (사이드바 토글 + `+`) 사이 또는 끝에 "오늘" 버튼을 추가. macOS Calendar 의 결은 보통 좌측 영역(달력 이동 컨트롤)과 묶이는 편이라 사이드바 토글 옆이 자연스럽다. 위치는 직접 시각 확인하며 골라도 OK.

- store 를 어떻게 받을지: `FloatingToolbar` 가 지금 `CalendarStore` 를 모른다. 두 가지 결:
  - **A. store 를 binding/주입.** `FloatingToolbar` 가 store 를 받아 `store.today()` 를 직접 호출. 가장 직관적.
  - **B. 클로저 콜백.** `var onToday: () -> Void` 를 받아 `FloatingToolbar` 에 위임. `ContentView` 가 store 를 보유한 경우 적합.

현재 `MonthlyCalendarView` 가 `@StateObject` 로 store 를 소유하고 있고, `ContentView` 는 store 를 모른다. 두 가지 선택:

1. store 를 `ContentView` 로 끌어올린 뒤 `MonthlyCalendarView` 와 `FloatingToolbar` 둘 다 `@ObservedObject` / `@EnvironmentObject` 로 공유.
2. `MonthlyCalendarView` 가 계속 store 를 소유하고, "오늘" 버튼만 `MonthlyCalendarView` 내부의 다른 위치로 옮기는 방식.

학습 차원에서 **A → 1번 옵션 (state lift-up + EnvironmentObject)** 을 권장. SwiftUI 의 흔한 패턴이고, 추후 키보드 단축키나 다른 위치에서도 store 접근이 편해진다.

- `ContentView` 에:
  ```swift
  @StateObject private var calendarStore = CalendarStore()
  // ...
  .environmentObject(calendarStore)
  ```
- `MonthlyCalendarView`:
  ```swift
  @EnvironmentObject private var store: CalendarStore
  // @StateObject private var store = CalendarStore()  ← 제거
  ```
- `FloatingToolbar`:
  ```swift
  @EnvironmentObject private var store: CalendarStore
  ```

> Vue 비유: `provide` / `inject` 와 거의 같은 결. `@StateObject` 는 소유자(provide), `@EnvironmentObject` 는 그 트리 어디서나 inject.

### 3) 버튼 UX

`HoverButton` 의 label 에 `Text("오늘")` 형태. 다른 두 버튼이 SF Symbol icon 인 만큼 텍스트 버튼이 시각적으로 살짝 튄다 — 폰트 크기 / 좌우 패딩으로 어색하지 않게 조율. 또는 `calendar.badge.clock` 같은 SF Symbol 로 가도 OK (그 경우 hover tooltip 으로 "오늘" 의미 보강 권장).

```swift
HoverButton {
    store.today()
} label: {
    Text("오늘")
        .font(.system(size: 12, weight: .medium))
        .foregroundStyle(.primary)
        .frame(height: 20)
        .padding(.horizontal, 6)
}
```

## 자가 점검
- 빌드 통과?
- prev 로 몇 달 뒤로 간 뒤 "오늘" 클릭 → 새 달(=오늘 달) 이 **오른쪽에서** 들어오는가? (forward)
- next 로 몇 달 앞으로 간 뒤 "오늘" 클릭 → 새 달이 **왼쪽에서** 들어오는가? (backward)
- 현재 달에서 클릭 시 슬라이드 깜빡임 없이 그대로인가?
- 17-1 의 오늘 셀 강조가 "오늘" 버튼으로 복귀 후에도 잘 보이는가?
- 퀴즈: 같은 달일 때 early return 을 안 하면 어떤 일이 벌어지는가? — `rebuild` 가 같은 grid 를 다시 계산. `referenceDate` 값이 거의 같지만 시/분/초가 달라서 `@Published` 가 emit → view 가 transition 까지 트리거할 수 있음. 시각적 깜빡임 / 불필요한 비용.
- 퀴즈: `referenceDate > now` 가 `.backward` 인 이유? — 보고 있는 달이 미래라면, 과거(오늘) 로 돌아가는 것 → "이전 달 방향" → `.backward`.

## Claude 리뷰 체크리스트
