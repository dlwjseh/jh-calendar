# 단계 2: 트래픽라이트 버튼 직접 제어

## 학습 목표
- SwiftUI 와 AppKit 이 한 앱 안에 공존한다는 것을 이해한다.
- `NSWindow.standardWindowButton(_:)` 로 빨/노/초 버튼을 직접 가져와 투명도(`alphaValue`) 를 0 으로 만들어 평소엔 안 보이게 한다.

## 사전 지식
- 단계 1 완료 — `.windowStyle(.hiddenTitleBar)` 가 적용된 상태.
- "View 의 라이프사이클" 개념 (React 의 `useEffect(..., [])` 같은 것이 SwiftUI 에선 `.onAppear { }` 또는 `.task { }`).

## Swift / SwiftUI 개념

### 1) SwiftUI 위에 AppKit 이 깔려 있다

macOS 에서 SwiftUI 앱은 결국 내부적으로 AppKit (NSApplication / NSWindow / NSView) 으로 실행된다. SwiftUI 가 "추상화 레이어" 인 셈.

| 추상 | 구현체 |
|---|---|
| `App` | `NSApplication` |
| `WindowGroup` 의 한 윈도우 | `NSWindow` |
| `View` | `NSView` (대부분 `NSHostingView`) |

→ SwiftUI 에서 닿지 않는 디테일은 AppKit API 로 직접 만질 수 있다. **트래픽라이트 버튼 제어가 정확히 그 케이스**.

다른 언어 비유: React Native 에서 native 모듈로 내려가는 것과 비슷하다.

### 2) `NSApplication.shared.windows` 와 `NSWindow.standardWindowButton`

```swift
import AppKit

if let window = NSApplication.shared.windows.first {
    let close = window.standardWindowButton(.closeButton)     // NSButton?
    let mini  = window.standardWindowButton(.miniaturizeButton)
    let zoom  = window.standardWindowButton(.zoomButton)
    // 각각 옵셔널이다 — 윈도우 스타일에 따라 nil 일 수도 있음
}
```

- `standardWindowButton(_:)` 는 `NSWindow.ButtonType` 을 받아 해당 버튼(`NSButton?`) 을 돌려준다.
- 셋 다 `NSButton` 이고, `alphaValue: CGFloat` 프로퍼티로 투명도를 0~1 로 설정 가능.

### 3) "윈도우가 이미 만들어진 시점" 에 접근하기

`NSApplication.shared.windows` 는 앱 시작 직후엔 비어 있을 수 있다. 윈도우가 화면에 올라온 뒤에 접근해야 안전하다.

→ SwiftUI 에서 자주 쓰는 훅:

```swift
ContentView()
    .onAppear {
        // ContentView 가 화면에 올라왔을 때 1회 실행
    }
```

`.onAppear` 는 React 의 `useEffect(() => { ... }, [])` 와 의미가 비슷하다 (정확히 같진 않다 — 뷰가 다시 등장하면 또 호출될 수 있음).

### 4) 옵셔널 처리 — `if let`

Swift 의 옵셔널은 TS 의 `T | null` 과 비슷하지만 더 엄격하다.

```swift
if let window = NSApplication.shared.windows.first {
    // 여기 안에서는 window 가 NSWindow (옵셔널 풀린 상태)
}
```

오늘은 `if let` 한 가지만 알면 충분.

## 구현 가이드

수정할 파일: `JHCalendar/ContentView.swift`.

### 골격

```swift
import SwiftUI
import AppKit  // NSWindow, NSApplication 쓸 거니까

struct ContentView: View {
    var body: some View {
        Color.clear
            .frame(minWidth: 900, minHeight: 600)
            .onAppear {
                // TODO: NSApplication.shared.windows.first 에서 윈도우 가져오기
                // TODO: 세 standardWindowButton 의 alphaValue 를 0 으로
            }
    }
}
```

### 힌트

- 세 버튼 타입을 매번 풀어 쓰는 대신 배열로 묶어 반복하면 깔끔해진다:
  ```swift
  let types: [NSWindow.ButtonType] = [.closeButton, .miniaturizeButton, .zoomButton]
  for t in types {
      window.standardWindowButton(t)?.alphaValue = 0
  }
  ```
  `?.` 는 옵셔널 체이닝 — JS/TS 와 같은 의미.
- `import AppKit` 안 하면 `NSApplication`, `NSWindow.ButtonType` 같은 게 안 잡힌다.
- `NSApplication.shared.windows.first` 가 `nil` 일 수 있으니 `if let` 으로 감싸기.

> ⚠️ 이 단계에선 **버튼을 항상 안 보이게** 만들기만 한다. 호버는 다음 단계.

## 조금 더 (선택)
- 더 정석적인 방법은 `NSWindowDelegate` 를 쓰거나 `NSViewRepresentable` 로 윈도우 핸들을 받아오는 것이다. 지금은 학습 흐름상 가장 짧은 경로 (`NSApplication.shared.windows.first`) 를 쓰지만, 멀티 윈도우 앱이 되면 이 방식은 한계가 있다. 나중에 다듬는다.
- `isHidden = true` 와 `alphaValue = 0` 의 차이: `isHidden` 은 hit-test 자체에서 빠지므로 단축키 처리 등에 영향이 갈 수 있다. `alphaValue = 0` 은 "보이지 않을 뿐 존재" 라서 페이드 애니메이션과 잘 맞는다 — 그래서 이쪽을 택한다.
