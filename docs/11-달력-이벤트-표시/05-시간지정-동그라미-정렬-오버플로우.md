# 단계 5: 시간 지정 동그라미 + 정렬 + 오버플로우(+N)

> 새 Swift/SwiftUI 문법 없음(`sorted(by:)`·조건 분기·View 조합은 기존 범위). **작업 가이드**만 둔다.

## 작업 목표
같은 셀에서 **시간 지정 이벤트**를 "카테고리 색 동그라미 + 이벤트명" 으로 그리고, 종일/시간지정 **표시 순서**를 정하고, 한 셀에 이벤트가 많을 때 **`+N` 오버플로우**로 잘라 렌더 비용을 제한한다.

## 사전 산출물
- 04 의 종일 바 렌더링 + `DayCellView(events:)`

## 작업 가이드

**1) 시간 지정 행**
- `events` 에서 `isAllDay == false`.
- 한 행 = `HStack`: 작은 `Circle().fill(category.color).frame(width:6,height:6)` + `Text(e.name)`(작게, `.lineLimit(1)`).
- 종일 바와 같은 `VStack` 안에 이어 쌓는다.

**2) 정렬 (한 셀 안 순서)**
- 권장 순서: **종일 먼저 → 시간 지정(시작시각 오름차순)**.
- 02 에서 `startDate` 정렬로 가져왔으니 시간 지정끼리는 대체로 시간순. 종일/시간 묶음 순서만 명시적으로:

```swift
let sorted = events.sorted { a, b in
    if a.isAllDay != b.isAllDay { return a.isAllDay }   // 종일 먼저
    return a.startDate < b.startDate
}
```
- 이 정렬을 셀에서 매번 할 수도 있지만, 더 깔끔하게는 03 인덱스 버킷을 만들 때 정렬해 두는 것도 가능. **택일하되 한 곳에서만** 정렬할 것(이중 정렬 금지).

**3) 오버플로우 `+N` — 렌더 비용 제한**
- 셀 42개 × 무제한 행 = 레이아웃 비용·시각적 깨짐. 보이는 개수를 상수로 제한:

```swift
let maxVisible = 3
let visible = sorted.prefix(maxVisible)
let overflow = sorted.count - visible.count
// visible 렌더 후, overflow > 0 이면 Text("+\(overflow)") 한 줄
```
- `prefix` 는 무료에 가깝다(O(maxVisible)). 이게 "셀당 비용 상한" 을 만드는 마지막 장치 — 03 의 인덱스(조회 O(1))와 합쳐 **셀 렌더가 이벤트 수와 무관하게 상수 비용**이 된다.
- `maxVisible` 은 셀 높이에 따라 조정. 지금은 상수로 충분(셀 높이 동적 계산은 과설계).

## 직접 구현하기
- [ ] 시간 지정 이벤트: 색 동그라미 + 이름 행
- [ ] 종일 먼저 → 시간순 정렬 (한 곳에서만)
- [ ] `maxVisible` + `+N` 오버플로우
- [ ] 종일/시간 섞인 날에서 순서·표시 확인

> 다 끝나면 "다 했어" 라고 알리면 리뷰.

## 자가 점검 (구현 후)
- 빌드 통과?
- 한 날에 종일 1 + 시간 지정 2 → 종일이 위, 시간순 정렬?
- 이벤트 6개 만든 날 → 3개 + "+3" 처럼 잘리나? 셀 높이가 안 터지나?
- 퀴즈: `prefix(maxVisible)` 가 성능 설계에서 하는 역할은? (03 의 인덱스와 어떻게 합쳐지나)

## Claude 리뷰 체크리스트
- [ ] 시간 지정 = 동그라미 + 이름, 카테고리 색 정확
- [ ] 정렬이 한 곳에서만(이중 정렬 없음), 종일 먼저 규칙 일관
- [ ] `+N` 오버플로우로 셀당 렌더 비용 상한
- [ ] 셀이 여전히 "멍청" (필터/조회 없음)
