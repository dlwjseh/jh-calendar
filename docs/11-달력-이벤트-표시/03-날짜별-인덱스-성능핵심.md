# 단계 3: 날짜별 인덱스 만들기 (성능 핵심)

## 학습 목표
`[Event]` 를 **`[Date: [Event]]`** (그 날의 시작시각을 키로 한 날짜→이벤트 목록) 인덱스로 한 번에 변환하는 **순수 함수**를 만든다. 이게 이 기능 전체의 성능·확장 설계의 핵심이다.

## 사전 지식
- 02 에서 만든 `events: [Event]` (범위·정렬됨)
- `Event.startDate` / `endDate` (01)
- `Calendar` / `DateComponents` → `BorderlessTimePicker` 에서 다룸 (재설명 X)

## 왜 인덱스인가 (성능 핵심)

각 셀이 "내 날짜의 이벤트" 를 직접 찾는 naive 방식:

```swift
// DayCellView 안에서 (안 좋은 예)
let mine = allEvents.filter { sameDay($0.startDate, cell.date) }
```

- 셀 42개 × 매 렌더마다 전체 이벤트 스캔 = **O(셀 수 × 이벤트 수)**.
- SwiftUI 는 상태 변할 때 `body` 를 자주 다시 부른다 → 그때마다 42번 필터.

인덱스 방식: 부모가 **한 번** `[Date:[Event]]` 를 만들고(이벤트 1회 순회 = O(이벤트 수)), 각 셀은 `index[cell.date]` 로 **O(1) 조회**.

- 전체: O(셀 수 + 이벤트 수). 셀은 필터를 아예 안 한다 → 셀 재렌더가 싸다.
- 솔직히: 수십~수백 개 규모면 naive 도 안 느리다 (memory: 조기 최적화 경계). **그래도 인덱스를 쓰는 더 큰 이유는 "멀티데이 확장 지점을 한 곳에 가둔다"** 는 설계상의 이점이다 — 06 에서 이어짐.

## Swift / SwiftUI 개념 (새 개념)

### Dictionary
Java `HashMap<K,V>` / JS 객체·`Map` 에 해당. `[Date: [Event]]` = "Date → Event 배열".

```swift
var dict: [Date: [Event]] = [:]
dict[key, default: []].append(event)   // 없으면 [] 로 시작해서 append
```
`subscript(_, default:)` 패턴은 Java 의 `computeIfAbsent` 와 같은 역할.

### Dictionary(grouping:by:)
컬렉션을 키 기준으로 한 방에 묶기. **Java `Collectors.groupingBy`**, JS 의 reduce-to-map 과 같다.

```swift
let byDay = Dictionary(grouping: events) { event in
    Calendar.current.startOfDay(for: event.startDate)
}
// 결과: [Date(그 날 00:00) : [그 날 이벤트들]]
```

### Calendar.startOfDay(for:) — 키 정규화 (새 측면)
`Date` 는 시:분:초까지 있는 한 시점이다. `2026-05-18 14:30` 과 `2026-05-18 00:00` 은 **다른 키**다. 그래서 "같은 날" 로 묶으려면 **그 날 00:00 으로 정규화**해서 키로 써야 한다.
- 셀 쪽 조회도 **동일하게** `startOfDay(for: cell.date)` 로 키를 만들어야 일치한다. (양쪽 키 생성 규칙이 같아야 한다 — 가장 흔한 버그 포인트.)

### 순수 함수로 분리
입력(이벤트, 범위) → 출력(인덱스)만 있는 부수효과 없는 함수. 테스트 쉽고, **멀티데이 로직이 바뀔 단 한 곳**이 된다.

### 멀티데이 확장 지점 (지금은 주석만)
미래엔 이 함수가 `startOfDay(start) ... startOfDay(end)` 범위의 **모든 날에** 같은 이벤트를 append 하도록만 바뀐다. 그때 `Dictionary(grouping:)` → 수동 루프로 교체:

```swift
// 미래(멀티데이) 스케치 — 지금 구현 X, 주석으로 의도만 남겨둘 것
// var index: [Date:[Event]] = [:]
// for e in events {
//   var d = cal.startOfDay(for: e.startDate)
//   let last = cal.startOfDay(for: e.endDate)
//   while d <= last { index[d, default: []].append(e); d = cal.date(byAdding:.day,value:1,to:d)! }
// }
```
**핵심: 셀/조회 코드는 그대로다. 바뀌는 곳은 이 함수 내부 한 곳.** 이게 인덱스 설계의 진짜 이득.

### 어디서 호출하나
`MonthlyCalendarView` 에서 `events` 로부터 파생값으로 1회 계산:

```swift
private var eventsByDayIndex: [Date: [Event]] {
    eventsByDay(events)        // events 바뀔 때만 사실상 의미 있는 변화
}
```
- computed property 면 body 호출마다 재계산되지만 O(이벤트 수)라 이 규모엔 무해. 더 엄격히 캐시하고 싶으면 `CalendarStore` 로 옮겨 `events` 주입 시 1회 계산(메서드)하는 방식도 가능 — **지금은 computed 로 충분**, 과설계 금지.
