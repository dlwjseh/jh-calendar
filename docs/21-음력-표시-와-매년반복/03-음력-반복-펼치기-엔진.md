# 단계 3: 음력 반복 펼치기 엔진

> 이번 단계의 **핵심**: "매년 음력 4월 13일" 을 화면(양력 그리드)의 **올바른 양력 날짜들**로 펼친다. 음력→양력 변환을 `enumerateDates` 에 맡기는 게 포인트.

## 학습 목표
- `RecurrenceExpander` 에 `.yearlyLunar` 케이스를 추가한다.
- **음력 캘린더로** `enumerateDates` 를 돌려, 매칭 컴포넌트(월/일)를 **음력으로 해석**시켜 매년의 양력 날짜를 얻는다.
- 음력 날짜가 없는 해(음력 30일이 없는 달 등)는 자동 skip 됨을 이해한다.

## 사전 산출물
- `RecurrenceExpander.swift` (19-04) — `occurrences(of:in:)` 의 `switch event.recurrence`, 특히 `.yearly` 케이스(양력 월/일 매칭) 구조.
- `LunarDate` 헬퍼 (01), `yearlyLunar` 케이스 + 라벨 (02).

## Swift / SwiftUI 개념

### `enumerateDates` 는 "어느 캘린더가 부르냐" 로 해석이 바뀐다
양력 `.yearly` 는 이렇게 돌렸다:

```swift
let cal = Calendar.current                 // 그레고리력
var comps = DateComponents()
comps.month = 5; comps.day = 29
cal.enumerateDates(startingAfter: from, matching: comps, matchingPolicy: .strict) { date, _, stop in ... }
//  ^ "양력 5월 29일" 인 날들을 찾음
```

핵심: `enumerateDates` 는 **호출한 캘린더의 역법으로** `matching` 컴포넌트를 해석한다. 그러니 **음력 캘린더로 호출**하면 같은 `comps.month/day` 가 **음력 월/일**로 해석된다.

```swift
let lunar = LunarDate.calendar             // Calendar(identifier: .chinese)
var comps = DateComponents()
comps.month = 4; comps.day = 13
lunar.enumerateDates(startingAfter: from, matching: comps, matchingPolicy: .strict) { date, _, stop in
    // date = "음력 4월 13일" 에 해당하는 ★양력★ Date (매년 다른 양력 날)
}
```

→ 우리가 직접 음력→양력 환산표를 만들 필요가 없다. **콜백이 주는 `date` 가 이미 양력 시점**이다(`Date` 는 절대 시점이니까 — 01단계 개념). 그걸 양력 `startOfDay` 로 정규화해 담으면 그리드와 키가 맞는다.

> Java 비교: "매년 같은 (양력) 월/일" 은 `MonthDay` 로 쉽지만, "매년 같은 **음력** 월/일 → 양력 날짜" 는 표준 라이브러리에 음력 크로놀로지가 없어 직접 해야 한다. Foundation 은 `.chinese` 캘린더로 `enumerateDates` 한 줄이면 된다.

### 없는 날은 `.strict` 가 알아서 skip
음력 달은 29일 또는 30일이다. 그래서 "음력 4월 30일" 은 그 4월이 작은달(29일)인 해엔 **존재하지 않는다.** 양력 `2/29` 를 평년에 건너뛴 것과 똑같이, `matchingPolicy: .strict` 면 enumerateDates 가 그런 해를 자동으로 빼준다(19-04 에서 본 성질). → 추가 분기 불필요.

## 구현 가이드

### `.yearlyLunar` 케이스 추가
`RecurrenceExpander.swift` 의 `switch` 에 케이스 추가. 구조는 `.yearly` 와 거의 같고, **(a) 캘린더를 음력으로**, **(b) 월/일을 음력 컴포넌트로** 뽑는 것만 다르다.

```swift
case .yearlyLunar:
    let lunar = LunarDate.calendar
    let l = LunarDate.components(from: event.startDate)   // 음력 월/일
    var comps = DateComponents()
    comps.month = l.month
    comps.day   = l.day

    let floor = max(start, cal.startOfDay(for: interval.start))   // cal = Calendar.current (위에서 선언됨)
    let from  = cal.date(byAdding: .day, value: -1, to: floor)!
    lunar.enumerateDates(startingAfter: from, matching: comps, matchingPolicy: .strict) { date, _, stop in
        guard let date, date <= interval.end else { stop = true; return }
        result.append(cal.startOfDay(for: date))   // 양력 0시로 정규화 (그리드 키와 일치)
    }
    return result
```

힌트:
- `start`(원래 시작일 0시)와 `cal`(`Calendar.current`)은 함수 상단에서 이미 선언돼 있으니 그대로 쓴다.
- `enumerateDates` 는 **음력(`lunar`)** 로 부르지만, 경계 비교(`date <= interval.end`)와 정규화(`cal.startOfDay`)는 **양력(`cal`)** 으로 한다. 섞는 게 의도다 — 찾기는 음력 렌즈, 저장은 양력 시점.
- `from = floor - 1일` 로 두는 이유: `startingAfter` 는 **초과(exclusive)** 라, `floor` 당일이 occurrence 면 놓치지 않으려고 하루 앞에서 시작(19-04 양력과 동일 트릭).

### 그 외는 손댈 필요 없음
- `MonthlyCalendarView` / `DayPopupDialog` 의 표시 쪽은 이미 `RecurrenceExpander.occurrences(...)` / `occurs(...)` 를 호출한다(19-04). enumerator 가 새 케이스를 처리하면 **표시는 자동으로 따라온다.**

## 자가 점검
- 빌드 통과?
- 오늘(2026-05-29, 음력 4.13)에 `매년 음력 4월 13일` 이벤트를 만들면 **오늘 셀**에 뜨나?
- **다음/이전 해**로 달을 넘기면, 그 해의 음력 4월 13일에 해당하는 **양력 날짜**(매년 다름)에 뜨나? 양력 5/29 에 고정돼 있으면 잘못 — 음력으로 안 돌고 있는 것.
- 양력 `매년`(=`.yearly`) 이벤트와 비교: 양력은 매년 같은 날, 음력은 매년 양력 날짜가 움직여야 정상.
- 퀴즈: `enumerateDates` 를 `lunar` 로 부르는데 콜백 `date` 는 왜 양력으로 쓸 수 있나? → `Date` 는 캘린더와 무관한 절대 시점. 음력으로 "찾기"만 했고, 그 결과 시점을 양력 렌즈로 "읽는" 것.

## Claude 리뷰 체크리스트
- [ ] `enumerateDates` 를 **음력 캘린더**로 호출 (월/일이 음력으로 해석되게)
- [ ] 경계/정규화는 양력(`Calendar.current`)으로 — 그리드 키와 일치
- [ ] 없는 음력 날(작은달 30일)은 `.strict` 로 skip, 별도 분기 없음
- [ ] 표시 코드(MonthlyCalendarView/DayPopupDialog)는 안 건드림 (엔진만 확장)
- [ ] `.yearly` 와의 중복을 과하게 추상화하지 않음 (지금 규모엔 두 케이스 나란히가 명료)
