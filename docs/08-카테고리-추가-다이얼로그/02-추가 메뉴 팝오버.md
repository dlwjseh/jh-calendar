# 단계 2: 추가 메뉴 팝오버 (말풍선)

## 학습 목표
- `+` 버튼 옆에 **화살표 달린 말풍선** (팝오버) 을 띄운다.
- 팝오버 안에 **폴더 / 카테고리** 두 메뉴 항목을 두고, 클릭하면 해당 다이얼로그 상태를 켠다.
- **다이얼로그 상태** (`isAddFolderPresented` / `isAddCategoryPresented`) 를 `ContentView` 로 끌어올리고 `Sidebar` 에 `@Binding` 으로 넘긴다.

## 사전 지식
- 단계 01 — `Sidebar` 안에 `@State isAddMenuPresented` 와 `+` 버튼이 있음.
- `@Binding<Bool>` 끌어올리기 → [03-사이드바-슬라이드](../03-사이드바-슬라이드/) 참고

## Swift / SwiftUI 개념

### 1. `.popover()` — 시스템 제공 말풍선

SwiftUI 의 `.popover(isPresented:)` 는 macOS 에서 **NSPopover** 를 띄운다. **둥근 사각형 + 화살표 + 시스템 배경** 이 자동으로 그려진다. 우리가 원하는 "말풍선" 모양이 바로 이거다.

```swift
HoverButton { ... } label: { ... }
    .popover(
        isPresented: $isAddMenuPresented,
        attachmentAnchor: .rect(.bounds),   // 어디에 붙을지 (이 view 의 bounds 기준)
        arrowEdge: .bottom                  // 화살표가 어느 edge 에서 나올지
    ) {
        AddMenuPopover( ... )                // 팝오버 내용
    }
```

핵심 파라미터:
- **`isPresented:`** — `Binding<Bool>`. true 면 표시, false 면 닫힘. 외부 클릭 시 시스템이 자동으로 false 로 돌려놓는다.
- **`attachmentAnchor:`** — 팝오버가 source view 의 어디에 anchor 되는지. `.rect(.bounds)` 가 보통 무난 (source 의 전체 영역 기준).
- **`arrowEdge:`** — source view 의 **어느 edge 에서 화살표가 나오는지**.
  - `.bottom` → source 아래쪽 edge 에 붙음 → 팝오버는 **source 아래** 에 뜨고, 화살표는 위쪽 (source 를 가리킴)
  - `.top` → 반대 (팝오버가 source 위에 뜸)
  - `.leading` / `.trailing` 도 가능

> 우리 요구사항: + 버튼 **아래** 에 말풍선이 뜨고, 화살표는 + 버튼 쪽 (위) 으로 → **`arrowEdge: .bottom`**.
>
> 직관적으로 헷갈리면, `.top` / `.bottom` 둘 다 한 번씩 켜 보고 어느 쪽이 원하는 모양인지 눈으로 확인하는 게 빠르다.

> Java/Spring 비유는 마땅치 않다. 웹 쪽에서 비슷한 발상은 popper.js / floating-ui 같은 floating element 라이브러리.

### 2. 외부 클릭 / ESC 로 자동 닫힘

`.popover()` 는 시스템이 **dismiss 동작을 자동 처리** 한다:
- 팝오버 바깥 클릭 → `isPresented` 가 자동으로 `false` 로
- ESC 키 → 자동 닫힘
- 다른 창으로 포커스 이동 → 자동 닫힘

→ 우리가 따로 close 핸들러 붙일 필요 없음. 메뉴 항목을 클릭했을 때만 명시적으로 `isAddMenuPresented = false`.

### 3. 다이얼로그 상태 끌어올리기 (`ContentView` 로)

이번 단계부터 두 다이얼로그 상태가 등장:

```swift
struct ContentView: View {
    @State private var isSidebarVisible = false
    @State private var isAddFolderPresented = false      // 추가
    @State private var isAddCategoryPresented = false    // 추가

    var body: some View {
        // ...
        Sidebar(
            isAddFolderPresented: $isAddFolderPresented,
            isAddCategoryPresented: $isAddCategoryPresented
        )
        // ...
    }
}
```

```swift
struct Sidebar: View {
    @State private var isAddMenuPresented = false        // 기존 (로컬)
    @Binding var isAddFolderPresented: Bool              // 추가
    @Binding var isAddCategoryPresented: Bool            // 추가
    @State private var folders: [Folder] = Folder.sample
    // ...
}
```

**왜 메뉴 상태는 로컬, 다이얼로그 상태는 ContentView?**
- 팝오버는 `+` 버튼 옆 (사이드바 안) 에 뜸 → 사이드바가 알면 충분
- 다이얼로그는 **사이드바 + 캘린더 전체를 덮는** dim 배경 + 중앙 카드 → 사이드바 너비 (240) 를 벗어나야 하니 **ContentView 가 그려야 함** → 상태도 ContentView 소유

> 기능 03 의 `isSidebarVisible` 와 같은 결. **그리는 주체가 상태를 소유한다.**

## 구현 가이드

### 1. `AddMenuPopover.swift` 신설

`JHCalendar/Features/Sidebar/AddMenuPopover.swift`:

```swift
import SwiftUI

struct AddMenuPopover: View {
    @Binding var isAddMenuPresented: Bool
    @Binding var isAddFolderPresented: Bool
    @Binding var isAddCategoryPresented: Bool

    var body: some View {
        VStack(alignment: .leading, spacing: 4) {
            menuItem(title: "폴더", systemImage: "folder") {
                isAddMenuPresented = false
                isAddFolderPresented = true
            }
            menuItem(title: "카테고리", systemImage: "tag") {
                isAddMenuPresented = false
                isAddCategoryPresented = true
            }
        }
        .padding(8)
        .frame(minWidth: 140)
    }

    private func menuItem(
        title: String,
        systemImage: String,
        action: @escaping () -> Void
    ) -> some View {
        // TODO: Button + Label 조합. HoverButton 재사용도 OK.
        // 힌트: Button { action() } label: { Label(title, systemImage: systemImage) }
        //       .buttonStyle(.plain) 또는 자체 hover 스타일
        EmptyView()
    }
}
```

> SF Symbols `folder`, `tag` 외에 `square.grid.2x2`, `circle.grid.cross` 등도 카테고리 느낌. 취향대로.

> `Button` 의 기본 스타일 (`.borderedProminent` 등) 은 팝오버 안에선 어색할 수 있다. `.buttonStyle(.plain)` 으로 시작해 hover 시 배경만 살짝 띄우는 패턴이 깔끔.

### 2. `Sidebar` 에 `.popover()` 붙이기

```swift
HoverButton {
    isAddMenuPresented.toggle()
} label: {
    Image(systemName: "plus")
    // ...
}
.popover(
    isPresented: $isAddMenuPresented,
    attachmentAnchor: .rect(.bounds),
    arrowEdge: .bottom
) {
    AddMenuPopover(
        isAddMenuPresented: $isAddMenuPresented,
        isAddFolderPresented: $isAddFolderPresented,
        isAddCategoryPresented: $isAddCategoryPresented
    )
}
```

힌트:
- 단계 01 에서 넣었던 `print` 는 이제 빼도 됨 (팝오버 자체가 시각적 확인)
- `arrowEdge` 가 헷갈리면 `.top`, `.bottom` 둘 다 시도

### 3. `ContentView` 에 다이얼로그 상태 추가

```swift
struct ContentView: View {
    @State private var isSidebarVisible = false
    @State private var isAddFolderPresented = false
    @State private var isAddCategoryPresented = false

    var body: some View {
        HStack(spacing: 0) {
            Sidebar(
                isAddFolderPresented: $isAddFolderPresented,
                isAddCategoryPresented: $isAddCategoryPresented
            )
            .frame(width: isSidebarVisible ? 240 : 0, alignment: .leading)
            .clipped()
            // ...
        }
        // 단계 03 에서 여기 ZStack + 다이얼로그 overlay 추가 예정
        .onChange(of: isAddFolderPresented) { _, new in
            print("isAddFolderPresented = \(new)")          // 단계 03 까진 확인용
        }
        .onChange(of: isAddCategoryPresented) { _, new in
            print("isAddCategoryPresented = \(new)")
        }
    }
}
```

> `onChange(of:)` 는 값이 바뀔 때마다 클로저 실행 — Vue 의 `watch` 와 비슷. 단계 03 에서 dim + dialog overlay 가 들어가면 print 는 빼도 됨.
