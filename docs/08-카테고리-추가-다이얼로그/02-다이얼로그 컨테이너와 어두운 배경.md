# 단계 2: 다이얼로그 컨테이너 + 어두운 배경 + 닫기 3종

## 학습 목표
- 화면 전체를 덮는 어두운 dim 레이어 위에 **중앙 카드** 를 띄우는 모달 패턴을 구현한다.
- **세 가지 닫기 방법** 을 다 붙인다: 취소 버튼 (다음 단계) / 배경 클릭 / ESC 키.
- 이벤트 전파 개념을 짚는다 — 카드 안을 클릭했을 땐 닫히지 않아야 한다.

## 사전 지식
- 단계 01 — `isAddCategoryPresented: Bool` 이 `ContentView` 에 있고 `+` 버튼이 그것을 `true` 로 만든다.
- `ZStack` / `overlay` → [01-타이틀바-호버표시](../01-타이틀바-호버표시/) 및 `ContentView` 의 traffic light overlay 참고.

## Swift / SwiftUI 개념

### 1. 모달 overlay 패턴 — `.sheet` 가 아닌 직접 ZStack

SwiftUI 기본 제공 `.sheet(isPresented:)` 는 macOS 에서 **타이틀바 아래로 슬라이드 다운하는 시스템 시트** 다. 화면 중앙에 어두운 배경 + 카드를 띄우는 형태가 아니다. 우리가 원하는 모양에 안 맞으므로 **직접 ZStack 으로 만든다**.

기본 골격:

```swift
ZStack {
    // 1. 메인 컨텐츠 (사이드바 + 캘린더)
    HStack { ... }

    // 2. 다이얼로그 레이어 (조건부)
    if isAddCategoryPresented {
        Color.black.opacity(0.4)                // dim
            .ignoresSafeArea()                   // 화면 전체로 확장
            .onTapGesture {
                isAddCategoryPresented = false   // 배경 클릭 → 닫기
            }

        AddCategoryDialog(
            isPresented: $isAddCategoryPresented
        )
        // 카드 자체는 중앙. ZStack default alignment 가 .center 라 그대로 두면 가운데.
    }
}
```

### 2. `.onTapGesture` — 이벤트 전파 주의

> Vue 비유: `@click.self` 와 비슷한 발상. 자식에서 발생한 클릭이 부모로 올라오면 안 되는 케이스.

배경 (`Color.black.opacity`) 의 `.onTapGesture` 만 두면 동작은 한다. 문제는 **카드를 ZStack 의 자식으로 두면, 카드 안 클릭이 dim 의 onTapGesture 까지 도달할 수 있는지** — 결론은 **SwiftUI 의 `.onTapGesture` 는 해당 view 의 영역에 한정** 되므로, 카드 영역 안에서 발생한 탭은 dim 의 onTapGesture 를 발동시키지 않는다. (각 view 가 자기 hit-test 영역에 대해 독립적으로 처리.)

다만 **카드 위에 또 다른 클릭 동작이 없는 빈 영역** 이 있고, 그 영역을 클릭하면 어떤 view 가 받느냐가 미묘해진다. 안전하게 카드 자체에 `.contentShape(Rectangle())` 을 주거나, 카드의 배경 view 자체가 hit-test 가 가능하면 OK.

요약하면:
- 배경 dim 에 `.onTapGesture` → 배경 클릭 시 닫기
- 카드 영역은 자기 영역이라 배경의 탭을 가로채므로 그대로 두면 됨
- 헷갈리면 카드에 `.contentShape(Rectangle())` 한 줄 추가

### 3. `.onKeyPress` / `.keyboardShortcut` — ESC 로 닫기

방법 A — `.keyboardShortcut` (가장 간단, 권장):

```swift
Button("취소") { isPresented = false }
    .keyboardShortcut(.cancelAction)   // ESC + Cmd+. 자동
```

`.cancelAction` 은 macOS 의 표준 "취소" 의미 — **ESC 키와 Cmd-마침표** 가 자동으로 묶인다. 별도 키 핸들러 없이도 ESC 닫기가 된다. **취소 버튼이 있다면 이 방법이 가장 idiomatic.**

> Java/Spring 비유는 없음 — SwiftUI 에만 있는 macOS HIG (Human Interface Guidelines) 표준 단축키 매핑.

방법 B — `.onKeyPress(.escape)` (좀 더 일반적):

```swift
.onKeyPress(.escape) {
    isPresented = false
    return .handled
}
```

이 방법은 버튼 없이도 ESC 만으로 닫고 싶을 때 쓴다. 다만 view 가 **키 포커스를 받고 있어야** 동작 — 그래서 카드 view 에 `.focusable()` 을 같이 붙이거나, 안에 `TextField` 같이 자연스럽게 포커스를 가져가는 자식이 있어야 한다 (다음 단계에서 TextField 가 들어오므로 OK).

→ 추천: 단계 03 에서 취소 버튼을 만들면서 `.keyboardShortcut(.cancelAction)` 을 붙이면 한 줄로 끝. 이번 단계에선 일단 닫기를 위한 자리만 마련해두면 충분.

### 4. (선택) `.transition` 으로 부드럽게 등장

다이얼로그가 갑자기 나타나는 게 어색하면 `withAnimation` + `.transition` 조합으로 페이드 또는 스케일을 줄 수 있다.

```swift
// 토글 시
withAnimation(.smooth(duration: 0.2)) {
    isAddCategoryPresented = false
}

// 다이얼로그 view 에
.transition(.opacity.combined(with: .scale(scale: 0.96)))
```

> 기능 03 단계 03 (`.transition`) + 기능 07 단계 01 (`withAnimation` 함정) 참고. View identity 가 깨지는 케이스 아니라 안전.

## 구현 가이드

### 1. `AddCategoryDialog.swift` 신설 (placeholder)

`JHCalendar/Features/Sidebar/AddCategoryDialog.swift`:

```swift
import SwiftUI

struct AddCategoryDialog: View {
    @Binding var isPresented: Bool

    var body: some View {
        VStack(spacing: 16) {
            Text("카테고리 추가")
                .font(.headline)
            Text("(다음 단계에서 입력 폼 추가 예정)")
                .foregroundStyle(.secondary)

            HStack {
                Button("취소") { isPresented = false }
                    .keyboardShortcut(.cancelAction)   // ESC 도 같이
                Spacer()
                Button("저장") { isPresented = false }
                    .keyboardShortcut(.defaultAction)
            }
        }
        .padding(24)
        .frame(width: 360)
        .background(.background)            // 시스템 배경색 (다크모드 자동 대응)
        .clipShape(.rect(cornerRadius: 12))
        .shadow(color: .black.opacity(0.3), radius: 20, y: 8)
    }
}
```

> `.background(.background)` 는 시스템 동적 색상 — 라이트모드면 흰색, 다크모드면 어두운 회색. `.white` 로 박으면 다크모드에서 어색해진다.

### 2. `ContentView` 에 dim + dialog 레이어 추가

```swift
struct ContentView: View {
    @State private var isSidebarVisible = false
    @State private var isAddCategoryPresented = false

    var body: some View {
        ZStack {
            HStack(spacing: 0) {
                Sidebar(isAddCategoryPresented: $isAddCategoryPresented)
                    .frame(width: isSidebarVisible ? 240 : 0, alignment: .leading)
                    .clipped()
                ZStack(alignment: .topLeading) {
                    Color.clear
                    MonthlyCalendarView()
                    FloatingToolbar(isSidebarVisible: $isSidebarVisible)
                }
            }
            .overlay(alignment: .topLeading) { TrafficLightHoverArea() }

            // 다이얼로그 레이어 — 가장 위
            if isAddCategoryPresented {
                Color.black.opacity(0.4)
                    .ignoresSafeArea()
                    .onTapGesture {
                        isAddCategoryPresented = false
                    }
                AddCategoryDialog(isPresented: $isAddCategoryPresented)
            }
        }
        .frame(minWidth: 900, minHeight: 600)
        .ignoresSafeArea()
    }
}
```

힌트:
- `.overlay(alignment: .topLeading) { TrafficLightHoverArea() }` 위치는 그대로 두되, 그것이 다이얼로그 레이어 **아래** 에 있어도 다이얼로그가 가리니까 문제없음.
- `Color.black.opacity(0.4)` 의 0.4 값은 취향대로 — 0.3~0.5 사이가 보통 자연스럽다.
- `ZStack` 의 default alignment 는 `.center` 라서 `AddCategoryDialog` 는 자동으로 가운데에 뜬다.

### 3. (선택) 등장/사라짐 애니메이션

```swift
if isAddCategoryPresented {
    Color.black.opacity(0.4)
        .ignoresSafeArea()
        .onTapGesture {
            withAnimation(.smooth(duration: 0.18)) {
                isAddCategoryPresented = false
            }
        }
        .transition(.opacity)

    AddCategoryDialog(isPresented: $isAddCategoryPresented)
        .transition(.opacity.combined(with: .scale(scale: 0.96)))
}
```

그리고 단계 01 의 `+` 버튼 액션도 `withAnimation` 으로 감싸기:

```swift
HoverButton {
    withAnimation(.smooth(duration: 0.18)) {
        isAddCategoryPresented = true
    }
} label: { ... }
```

> 애니메이션은 학습 목표는 아니지만, 한 줄짜리니 같이 붙이고 가는 게 사용성에 좋다.
