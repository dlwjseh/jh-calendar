# 단계 1: 사이드바 헤더 + `+` 버튼 (상태 끌어올리기)

## 학습 목표
- 사이드바 상단에 헤더 영역을 만들고, **우측 끝에** `+` 버튼을 둔다.
- 버튼이 토글할 상태 `isAddCategoryPresented` 를 **올바른 위치** 에 둔다 — 누가 소유하는 게 맞는지 다시 한 번 짚는다.

## 사전 지식
- 기능 03 의 `isSidebarVisible` 패턴 — `ContentView` 가 `@State` 로 소유, 자식이 `@Binding<Bool>` 로 받기.
- 기능 04 의 `Sidebar.swift` 구조 — 현재 `VStack` 안에 폴더 목록만 있음.

### "어디에 상태를 둬야 하지?" 다시 생각하기

`+` 버튼은 **사이드바 안에** 있다. 자연스럽게 보면 `Sidebar` 가 `@State var isAddCategoryPresented` 를 가지면 될 것 같다. 하지만:

- 버튼을 누르면 떠야 하는 다이얼로그는 **사이드바를 포함한 전체 화면을 덮는** 어두운 배경 + 중앙 카드다.
- 사이드바 안에서 그리면 사이드바 너비 (240pt) 를 못 벗어난다.
- → 다이얼로그를 그리는 주체는 **사이드바보다 위쪽 (부모)** 이 되어야 한다.
- → 상태도 그 부모 (`ContentView`) 가 소유하는 게 일관됨. 사이드바는 `@Binding<Bool>` 로 받아 토글만 한다.

기능 03 의 `isSidebarVisible` 와 정확히 같은 구도다 — **버튼이 있는 곳과 상태가 있는 곳이 다르다.**

> Java/Spring 비유: 자식 컴포넌트가 직접 `model.attribute` 를 갖는 게 아니라, 상위 컨트롤러가 모델을 들고 자식 fragment 에 파라미터로 넘기는 그림. SwiftUI 에선 그게 `@Binding`.

## 구현 가이드

### 1. `ContentView` 에 상태 추가 + Sidebar 에 binding 전달

```swift
struct ContentView: View {
    @State private var isSidebarVisible = false
    @State private var isAddCategoryPresented = false   // 추가

    var body: some View {
        HStack(spacing: 0) {
            Sidebar(isAddCategoryPresented: $isAddCategoryPresented)   // binding 전달
                .frame(width: isSidebarVisible ? 240 : 0, alignment: .leading)
                .clipped()
            // ...
        }
        // 단계 02 에서 여기 어딘가에 다이얼로그 overlay 추가 예정
    }
}
```

### 2. `Sidebar` 에 헤더 추가

현재 `Sidebar.swift` 의 `VStack` 위에 헤더 행을 하나 둔다.

```swift
struct Sidebar: View {
    @Binding var isAddCategoryPresented: Bool             // 추가
    @State private var folders: [Folder] = Folder.sample

    var body: some View {
        VStack(alignment: .leading, spacing: 0) {
            // 헤더 (우측 끝에 + 버튼)
            HStack {
                Spacer()
                HoverButton {
                    // TODO: 상태 토글
                } label: {
                    Image(systemName: "plus")
                        .font(.system(size: 14, weight: .medium))
                        .foregroundStyle(.primary)
                        .frame(width: 20, height: 20)
                }
            }
            .padding(.horizontal, 12)
            .padding(.top, ...)   // 트래픽 라이트/플로팅 툴바와 시각적으로 어색하지 않게

            // 기존 폴더 목록 (VStack)
            VStack(alignment: .leading, spacing: 30) {
                // ... 기존 내용
            }
        }
        .frame(width: 240, alignment: .leading)
        .frame(maxHeight: .infinity, alignment: .topLeading)
        .background(.gray.opacity(0.08))
    }
}
```

힌트:
- 기존 `.padding(.top, 40)` 은 헤더가 그 자리를 차지하게 되니 외부 컨테이너에서 빼고, 헤더 자체의 `padding(.top)` 으로 옮겨주는 게 깔끔.
- 헤더 높이를 플로팅 툴바 (캘린더 쪽 위 toolbar) 와 시각적으로 맞추면 좋다. 정확한 값보다 **눈으로 보고 조정** 하는 게 빠름.

### 3. `+` 버튼 누르면 상태 토글

```swift
HoverButton {
    isAddCategoryPresented = true   // 또는 toggle()
} label: { ... }
```

이번 단계에선 다이얼로그 자체가 아직 없으므로, **확인용** 으로 `print` 를 하나 같이 두면 동작 검증이 쉽다:

```swift
HoverButton {
    print("+ 클릭, isAddCategoryPresented = \(!isAddCategoryPresented)")
    isAddCategoryPresented = true
} label: { ... }
```

> `isAddCategoryPresented = true` 인 상태에서 다시 눌렀을 때 어떻게 되어야 할까? 다이얼로그가 떠 있으면 `+` 버튼이 가려질 가능성이 높으니 (단계 02 에서 배경이 어두워지므로), 사실상 이 케이스는 거의 안 발생한다. 일단 `true` 로 세팅만 해도 OK.
