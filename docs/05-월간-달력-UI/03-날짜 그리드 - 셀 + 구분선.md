## Swift / SwiftUI 개념

### 1) `stride(from:to:by:)` — 새 개념
- **시작부터 끝까지 일정 간격으로 건너뛰며 순회** 하는 시퀀스. Java 의 `for (int i = 0; i < n; i += step)` 와 같은 위상.

```swift
stride(from: 0, to: cells.count, by: 7)   // 0, 7, 14, 21, ...
    .map { start in Array(cells[start..<start + 7]) }
```

- `to:` 는 **미포함** (반열린 구간).
- `through:` 버전도 있는데 그건 끝값 포함.

### 2) Array slice → Array 변환 — 새 개념
- `cells[0..<7]` 의 타입은 `ArraySlice<DayCell>` — 원본의 얕은 뷰.
- `ArraySlice` 는 **인덱스가 0부터 시작하지 않을 수 있다** (원본의 인덱스를 그대로 유지). slice 의 함정 포인트.
- `ForEach` 등에 안전하게 넘기려면 `Array(slice)` 로 새 배열로 승격.

> Java 의 `subList()` 가 원본을 참조하는 view 인 것과 비슷한 함정. 보통 `new ArrayList<>(list.subList(...))` 로 복사하는 패턴과 같다.

### 3) `VStack` 의 세로 공간 균등 분배 — 단계 02 의 가로 분할과 짝
- 단계 02 에선 `HStack` 자식에 `frame(maxWidth: .infinity)` → 가로 균등 분할.
- 같은 원리가 세로에도: **`VStack` 자식이 `.frame(maxHeight: .infinity)` 를 가지면 VStack 이 남는 세로 공간을 그 자식들에게 균등 분배.**
- 모든 행이 maxHeight: .infinity 면 → 행 높이 균등.

```swift
VStack(spacing: 0) {
    ForEach(rows, id: \.first?.id) { row in
        HStack(...) { /* 7 cells */ }
            .frame(maxHeight: .infinity)   // ← 이 줄이 핵심
    }
}
```

> Vue/CSS 의 `flex: 1` 과 동일한 발상. SwiftUI 도 결국 Flexbox 변형으로 보면 매핑이 깔끔.

### 4) `ForEach(_:id:)` — id 지정 트릭
- 04-2 에선 `ForEach(items)` 처럼 `Identifiable` 모델을 그대로 사용했다.
- 지금처럼 `rows: [[DayCell]]` (배열의 배열) 은 **행 자체에 id 가 없음** — `[DayCell]` 은 `Identifiable` 이 아니니까.
- 키 패스로 행 id 를 명시: `\.first?.id` → 각 행의 첫 셀 id 를 그 행의 id 로.

```swift
ForEach(rows, id: \.first?.id) { row in ... }
```

> JS 의 `key={...}` 와 같은 역할. SwiftUI 는 이 id 로 diff 해서 행 추가/이동/삭제를 추적.

### 5) `overlay` — 새 개념
- 어떤 view 위에 다른 view 를 **같은 크기로** 얹는다. 테두리 / 배지 / 그라데이션 용도. (단계 02 에서 요일 헤더 하단 Divider 를 깔 때 이미 한 번 썼다.)
- 셀 사각 테두리는 `Rectangle().stroke(...)` 를 overlay 로:

```swift
DayCellView(cell: cell)
    .overlay(
        Rectangle()
            .stroke(Color.gray.opacity(0.2), lineWidth: 0.5)
    )
```

- `.border(Color, width:)` 단축 표현도 거의 동등.

### 6) 이번 달 외 날짜의 흐림 처리
- `cell.isInCurrentMonth == false` 면 글자색을 더 흐리게.
- `.foregroundStyle(cell.isInCurrentMonth ? .primary : .tertiary)` — 시스템 컬러 위계 (1차/2차/3차) 를 그대로 활용.

## 구현 가이드

### 새 파일
`JHCalendar/Features/MonthlyCalendar/DayCellView.swift`

```swift
import SwiftUI

struct DayCellView: View {
    let cell: DayCell

    var body: some View {
        VStack(spacing: 0) {
            Text("\(cell.day)")
                .font(.caption)
                .foregroundStyle(cell.isInCurrentMonth ? .primary : .tertiary)
                // TODO: 폰트/패딩 디테일은 시각 맞춰가며 조정

            Spacer(minLength: 0)
        }
        .frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .top)
        .padding(.top, 6)
        .overlay(
            Rectangle()
                .stroke(Color.gray.opacity(0.2), lineWidth: 0.5)
        )
    }
}
```

### `MonthlyCalendarView` 수정
- 단계 02 의 `Spacer()` (또는 빈 자리) 가 있던 곳에 그리드를 채워넣는다.
- `rows: [[DayCell]]` 는 `init` 에서 한 번만 계산.

```swift
struct MonthlyCalendarView: View {
    private let referenceDate = Date()
    private let rows: [[DayCell]]

    init() {
        let cells = makeDayCells(for: Date())
        self.rows = stride(from: 0, to: cells.count, by: 7).map { start in
            Array(cells[start..<start + 7])
        }
    }

    // formatter / weekdayLabels — 단계 02 그대로

    var body: some View {
        VStack(alignment: .leading, spacing: 0) {
            // 년월 헤더 — 단계 02
            // 요일 헤더 — 단계 02

            // 일 그리드
            VStack(spacing: 0) {
                ForEach(rows, id: \.first?.id) { row in
                    HStack(spacing: 0) {
                        ForEach(row) { cell in
                            DayCellView(cell: cell)
                        }
                    }
                    .frame(maxHeight: .infinity)   // ← 행 높이 균등 분할
                }
            }
        }
        // 외곽 padding — 단계 02 + 필요 시 maxHeight 추가 (아래 참고)
    }
}
```

### 외곽 frame 보조
그리드가 화면 세로를 꽉 채우려면 **부모로부터 충분한 높이가 내려와야** 한다. 일단 위 코드 그대로 빌드해보고, 그리드가 짧게 잡히면 외곽 VStack 에 다음을 추가:

```swift
.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .topLeading)
```

## 조금 더 (선택)

### `LazyVGrid` 와의 비교 — 왜 안 썼나
- `LazyVGrid(columns:)` 는 **세로로 무한히 늘어나는 스크롤 그리드** (사진 갤러리, 무한 피드) 에 적합. "Lazy" = 보이는 부분만 그려서 성능 이득.
- 행 높이는 **콘텐츠 높이로 결정** 되고, 부모가 준 여분의 세로 공간을 행에 재분배하지 않음.
- 우리 케이스는 "고정 4~6주 × 7열, 화면을 꽉 채움" → 행 높이 균등 분할이 본질. `VStack` 의 공간 분배가 자연스럽게 들어맞음.
- LazyVGrid 로 같은 효과를 내려면 `GeometryReader` 로 부모 높이를 측정해 행 높이를 직접 계산해야 함 — 본 케이스엔 과잉.

### 인접 셀끼리 테두리가 이중으로 겹치는 현상
- `overlay(Rectangle().stroke())` 의 한계. 해결책: 셀에 top/leading 두 변만 그리고 그리드 자체에 trailing/bottom 마무리. 또는 단일 `Path` 로 한 번에 그리기.

### macOS 13+ 의 `Grid`
- Lazy 가 아닌 신형 그리드. 행/열을 명시적으로 짜는 형태. 셀 정렬에 강력. 이번 케이스에도 사용 가능하지만 `VStack/HStack` 만으로 충분해서 도입 안 함.
