## Swift / SwiftUI 개념

### 1) `Date` — "시점" 그 자체
- 한 점의 **절대 시각**. 타임존 / 로케일 / 달력 종류와 무관한, **그저 어떤 순간**.
- Java 의 `Instant` 와 같은 개념.
- 그래서 `Date` 자체로는 "몇 년, 몇 월, 몇 일" 을 모름 — 그건 **달력으로 해석한 결과**.

```swift
let now = Date()           // 지금 이 순간
let later = Date().addingTimeInterval(60 * 60)  // 한 시간 뒤
```

### 2) `Calendar` — "시점을 사람이 읽는 단위로 해석하는 자"
- `Date` 를 받아 **년/월/일/주/요일** 같은 사람이 다루는 단위로 쪼개거나, 반대로 그런 컴포넌트로 새 `Date` 를 만든다.
- 종류가 여러 개 (`gregorian`, `iso8601`, `japanese`, …). 우리는 그냥 시스템 기본을 쓰면 됨.
- Java 의 `Calendar` / `LocalDate` 가 합쳐진 역할.

```swift
let cal = Calendar.current
let year = cal.component(.year, from: Date())     // 2026
let month = cal.component(.month, from: Date())   // 5
```

### 3) `DateComponents` — "조각낸 결과 (또는 만들 재료)"
- `{ year, month, day, hour, weekday, … }` 같은 필드를 모아둔 값 타입.
- `Calendar` 와 짝지어서 `Date → DateComponents` (조각내기), `DateComponents → Date` (조립하기) 양쪽으로 쓴다.

```swift
var comps = DateComponents()
comps.year = 2026
comps.month = 5
comps.day = 1
let firstDay = Calendar.current.date(from: comps)!  // 2026-05-01 00:00 (시스템 타임존)
```

### 4) 알아두면 좋은 API 몇 개
- `cal.component(.weekday, from: date)` — 그 날짜의 요일. **일요일이 1, 토요일이 7** (기본 그레고리력 기준).
- `cal.range(of: .day, in: .month, for: date)` — 그 달의 일수 범위. 예: `1..<32` 면 31일까지.
- `cal.date(byAdding: .day, value: -3, to: date)` — 며칠 더하기/빼기.
- `cal.startOfDay(for: date)` — 그 날의 0시 시점.

### 5) 다른 언어와의 비교
- Java 의 `LocalDate.of(2026, 5, 1)` 한 줄이 Swift 에선 `DateComponents` 채우고 `Calendar.date(from:)` 로 변환하는 두 단계. 살짝 번거롭지만, 그만큼 **시점 자체 (`Date`)** 와 **그 해석 (`Calendar`)** 을 분리하는 설계.

### 만들 것
1. **`DayCell` 모델** — 그리드 한 칸을 표현하는 값
   ```swift
   struct DayCell: Identifiable {
       let id = UUID()
       let date: Date              // 그 칸이 가리키는 날짜 (0시)
       let day: Int                // 그 날짜의 일(day) 숫자 — makeDayCells 에서 미리 계산해 박아둠
       let isInCurrentMonth: Bool  // 이번 달 날짜인지 (앞뒤로 끌어온 이전/다음 달이면 false)
   }
   ```
   > `day` 를 computed property (`Calendar.current.component(.day, from: date)`) 로 둘 수도 있지만, 어차피 `makeDayCells` 가 매 칸마다 `Calendar` 를 들고 흐르므로 **그 자리에서 한 번만 계산해 stored** 로 박아두는 쪽이 자연스럽다. view 의 `body` 가 매 diff 마다 재계산하는 비용도 피하고, 모델이 `Calendar.current` 같은 외부 의존을 들고 다니지 않아 깔끔.
   > Java 로 치면 record 의 derived getter vs 생성자에서 미리 계산해 박아두는 final 필드 — immutable 값이면 후자가 디폴트.

2. **`makeDayCells(for referenceDate: Date) -> [DayCell]`** — 핵심 함수
   - 입력: 그 달의 아무 날짜 (보통 `Date()` 또는 `2026-05-15` 같은 한 점)
   - 출력: 화면에 그릴 칸들의 1차원 배열. **일요일부터 시작해서 토요일에 끝나는 완전한 주 단위.**
   - 4주짜리는 28개, 5주짜리는 35개, 6주짜리는 42개 — **달에 따라 가변**.

### 검증 방법 (이 단계 한정 — 임시)
SwiftUI 화면에 모델 결과를 임시로 띄워봐도 좋고, 더 간단하게는 `MonthlyCalendarView` 같은 view 를 만들어 `Text` 로 길이만 찍어봐도 OK.

```swift
struct MonthlyCalendarView: View {
    let cells = makeDayCells(for: Date())

    var body: some View {
        VStack(alignment: .leading) {
            Text("cells: \(cells.count)")               // 28 / 35 / 42 중 하나
            Text("first: \(cells.first?.day ?? -1)")    // 이전 달 끝자락 또는 1
            Text("last:  \(cells.last?.day ?? -1)")     // 이번 달 마지막 또는 다음 달 초입
        }
        .padding()
    }
}
```

그리고 `ContentView` 의 빈 `ZStack` 안에 `MonthlyCalendarView()` 를 잠깐 끼워 빌드 / 실행해서 숫자가 그럴듯한지 본다.
