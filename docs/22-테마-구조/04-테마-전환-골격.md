# 단계 4: 테마 전환 골격 (선택 / 추후)

> 이 단계는 **테마 추가와 색 결정을 끝낸 뒤** 진행한다. 01~03으로 "구조"는 이미 완성이고, 여기선 *여러 테마 중 하나를 골라 저장·적용*하는 연결점만 만든다.

## 작업 목표
선택된 테마 id를 저장하고(앱 재실행해도 유지), 루트에서 그 id로 테마를 해석해 주입한다. 사용자가 새 테마를 추가하면 여기에 "꽂기만" 하면 되도록.

## 사전 지식 / 개념
- `@AppStorage` 는 이미 다룸 → [20-카테고리-필터-와-사이드바-상태/02-사이드바-펼침-상태-유지.md](../20-카테고리-필터-와-사이드바-상태/02-사이드바-펼침-상태-유지.md) 참고. (UserDefaults 기반 영속 저장)
- 02단계의 `.environment(\.calendarTheme, ...)` 주입 — 여기에 `.classic` 대신 **해석된 테마**를 넣는 게 전부.

새 문법은 없다. 새로운 건 **"선택 id → 테마 인스턴스 해석 → 루트 재주입"** 패턴 하나.

## 구현 가이드
1. 테마들을 id로 식별 가능하게 (예: `CalendarTheme`에 `id`/이름 부여하거나, `enum ThemeID`로 매핑).
   ```swift
   extension CalendarTheme {
       static let classic = CalendarTheme(/* ... */)
       // TODO: 네가 추가할 테마들 — static let night = ...  / ocean = ...
   }
   ```
2. id → 테마 해석:
   ```swift
   // 지금은 classic 하나. 테마 추가하면 case 늘리면 됨.
   func resolveTheme(_ id: String) -> CalendarTheme {
       switch id {
       // TODO: case "night": return .night
       default: return .classic
       }
   }
   ```
3. 루트에서 선택값을 저장하고 주입:
   ```swift
   @AppStorage("selectedThemeId") private var themeId = "classic"
   // body:
   //   .environment(\.calendarTheme, resolveTheme(themeId))   // 02의 .classic 자리를 교체
   ```
4. 전환 UI(사이드바/설정 어딘가)에서 `themeId`를 바꾸면 → `@AppStorage`가 갱신 → 루트 재평가 → 전체 색 갱신.

힌트:
- `@AppStorage` 값이 바뀌면 그 뷰가 다시 그려지고, `.environment(...)`도 새 테마로 다시 주입된다 → 하위 전체가 갱신. (전환에 별도 작업 불필요)
- **새 테마 추가 = 3곳**: `CalendarTheme` static 인스턴스 + `resolveTheme` case + 전환 UI 옵션. 그게 끝.

## 직접 구현하기
- [ ] 테마 식별/해석(`resolveTheme`) 마련
- [ ] 루트 주입을 `resolveTheme(themeId)` 로 교체
- [ ] `@AppStorage`로 선택 저장
- [ ] 전환 UI에서 바꿔보고 즉시 반영 + 재실행 후 유지 확인

## 자가 점검 (구현 후)

- 앱 껐다 켜도 선택 유지되나? (`@AppStorage`)
- 새 테마 하나 추가가 정말 "3곳"으로 끝나나?
