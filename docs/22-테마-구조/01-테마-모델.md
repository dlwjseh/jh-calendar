# 단계 1: 테마 모델

## 학습 목표
이 단계를 마치면, 화면에 흩어진 색들을 **"역할"별 슬롯으로 묶은 값 타입**(`CalendarTheme`)을 정의하고, 현재 색 그대로인 기본 테마(`.classic`)를 만들 수 있다.

## 사전 지식
- `struct`, `extension`, `static let` (이전 단계들에서 사용)
- 색 관련: `Color`, `Color(red:green:blue:)` (04·08단계 등)
- 현재 색이 어디 박혀 있는지 → README 매핑 표

## Swift / SwiftUI 개념
이번 새 포인트는 **"의미론적 색 추상화"** — 문법보다 설계 개념이다.

- 지금 코드는 색의 **의미**(일요일/오늘/공휴일)와 **실제 값**(`.red`)이 한 곳에 붙어 있다. 이걸 떼어내서, 뷰는 "일요일 색"이라는 **역할**만 알고, 그 역할이 무슨 색인지는 테마가 정하게 한다.
- 묶음은 **값 타입 `struct`** 로. 테마는 "한 번 정해지면 안 바뀌는 설정 덩어리"라 `let` 프로퍼티 불변 struct가 적합하다.

> Java 비유: 색 상수를 여기저기 흩뿌리는 대신, 불변 **VO/record** 하나(`CalendarTheme`)에 모아두고 그걸 통째로 주입하는 것. 테마를 바꾼다 = 새 record로 통째 교체.
> `class`가 아니라 `struct`인 이유: 공유·변경되는 객체가 아니라 **복사되는 값**이기 때문. (참조 공유가 필요한 Store는 07단계에서 `class`/`ObservableObject`로 했던 것과 대비)

## 구현 가이드
> 정답 풀코드는 없음. 골격만 보고 직접 채운다.

**파일 위치**: `JHCalendar/Shared/Theme/Theme.swift` (새 폴더 `Shared/Theme/`)
- `Shared/` 는 sync root 라 **하위 폴더/파일을 두면 자동 인식** → pbxproj 편집 불필요. (CLAUDE.md "새 기능을 추가할 때" 참고)
- 테마는 플랫폼 무관(색·설정) → iOS에서도 재사용 → `Shared/` 가 맞는 자리.

```swift
import SwiftUI

struct CalendarTheme {
    let sunday: Color
    let saturday: Color
    // TODO: 나머지 슬롯 채우기 — weekdayText, subtleText, todayFill, todayText, holiday, gridLine, accent
}

extension CalendarTheme {
    static let classic = CalendarTheme(
        sunday: .red,
        saturday: .blue
        // TODO: 현재 코드의 색을 "그대로" 채운다 (색을 바꾸는 단계가 아님)
        //  - holiday 슬롯 값 = 지금 HolidayModels 의 Color.holiday = Color(red: 255/255, green: 99/255, blue: 71/255)
        //  - gridLine = Color.gray.opacity(0.2)  /  todayText = .white  ...
    )
}
```

힌트:
- 슬롯 **이름은 역할 기준**(README 표). `redColor` 같은 "값"이름 말고 `sunday` 같은 "역할"이름으로.
- `.classic` 의 목표는 **지금과 똑같이 보이게** 하는 것. 그래야 02·03 적용 후 화면이 안 변하는 걸로 "배선이 맞다"를 검증할 수 있다.
- 이 단계에선 아직 아무 뷰도 이걸 안 쓴다 → 빌드는 되지만 "미사용" 경고가 날 수 있음(정상).
